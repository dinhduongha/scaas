# Decisions (controller, the owner may override): (1) The facade keeps zether-prover's JSON commands (no command struct exists there): the facade
# reads and allow-lists the request, then hands the key object itself to api::call_with_key; no request field can carry a key. (2) A prover refusal
# is Argument, no detail (its text can name request values; DecryptBound included). (3) keygen and the verifiers are not exposed (Y / UA come from
# the handle; spec §10 "not exposed: verifiers"). (4) RECEIVER_X / AUDITOR openings needed a JSON command in zether-prover (openDisclosure, an API
# addition; schnorr::open_chaum_pedersen unchanged). (5) coin and account: any u32 (zether-prover's and clientkeys' rule), use 7 or 8. (6) The
# balance-cache bookkeeping (setCachedBalance, cacheAfterDebit, cacheAfterRollOver) is not ported: it needs x only through checkBalance, which is
# a command; the box is built here. (7) The cache plaintext is the caller's entries JSON as bytes (at most 1 MiB), returned as bytes.
# Notes: (1) The Zether key is not written into the manifest (its entries are UA kinds with account / index; a 0x0141 entry would also break
# unlock's WalletMismatch check, which derives the first entry's UA by kind). (2) Residual (spec §8.2): zether-prover's scalar copies and its
# arkworks scalar multiplications by x (not secret_mul). (3) recoverTransfer returns `s` (the sender's SENDER_S opening): intended disclosure.
# (4) A size query of scaas_ua_zether_call runs the command again (a new proof). (5) The vectors replay reproduces the prover's own vector files
# through the facade at their seeds; the schnorr_bls12381.json row has a fixed nonce, which no facade call takes (its key is checked).
