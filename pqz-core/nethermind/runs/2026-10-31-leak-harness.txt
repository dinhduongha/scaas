# PQZ native memory-leak test, 2026-10-31 (owner request 2026-10-31; branch fs3-t13-rollout, Task 13 final)
# Verdict: NO LEAK. All four runs CLEAN, 0 panics (status 3 PQZ-INPUT-PANIC = 0), anon memory flat or falling.

## Method
- Harness: the repo P/Invoke boundary harness (pqz-core/nethermind/Harness, as run by harness.sh), built with ref.sh
  assemblies in the pinned SDK container (mcr.microsoft.com/dotnet/sdk:10.0.402-resolute@sha256:6924c5c6…ca92).
- Run in the pinned base image nethermind/nethermind:2.2.0@sha256:5cc0061e…0a38 (.NET 10.0.13, MLDsa.IsSupported=True),
  container --memory 2g --cpus 4, scripts pqz-core/nethermind/leak/run.sh (start) + leak/sample.sh (sampler); the
  copies in the repo take S from the environment (the run used a session scratch dir).
- Library: libpqz_ffi.so copied from the live SCaaS testnet image, sha256
  dd0e7668eeb70972c89ad1b0bbccd7aca8a48a4bbfadbdad6655c0464afe5601, parameter set n2304-kmax4096.
- Corpus: the regenerated corpus (main, docs-drift 2026-10-31): 877 PQZ inputs (51 valid) + 38 ML-DSA inputs (7 valid);
  run D used only the 51 valid PQZ lines. Harness mutates each input (bitflips, byterun, extend, idswap, lenfield,
  opswap, random, stmtflip, tailflip, truncate) plus 1 GC-pressure thread; seed 7622.
- Sampling: the container's cgroup memory.stat anon / file (MiB) every 30 s (plus docker stats).
- Nothing touched the live stack; no transaction sent.

## Bound
It rests on run A: anon 576–577 -> 575 over the 17 min after warm-up (t 159–1184 s), at 1 MiB sample resolution.
Run A's own counts were lost with its log; at run B's rate (23,482 honest 01 per 20 min, ≈ 20 k in 17 min) that is
< ≈ 50 B retained per honest verify, i.e. none measurable. The mutated / rejected paths are covered by the same runs (≈ 1.8 M "out 00" per 20 min).

## Code
pqz_precompile writes its result into a 32-byte caller-owned buffer; no Rust-allocated memory crosses to C#. The
production cdylib (pqz-core/ffi/src, non-bin) has no Box::leak / mem::forget / into_raw (Box::leak appears only in the
pqz-vectors bin and the wasm builds, not in the library Nethermind loads).

## Node reading (inference)
The sealer's anon rise 617 -> 700 MiB under the PQZ e2e, then plateau, is consistent with .NET heap / allocator
warm-up, not a native leak (inference: the node itself was not measured with this method).
