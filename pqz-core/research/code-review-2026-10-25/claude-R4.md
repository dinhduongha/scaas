# R4 — Claude UltraCode review

Unit R4 is the precompile surface (code). It covers `pqz-core/stmt/src/`, `pqz-core/ffi/src/`, `pqz-core/ffi/pqz_ffi.h` and `pqz-core/nethermind/Nethermind.Pqz/`, in the frozen worktree the frozen review worktree at 008e196c. The review was read-only: nothing was built, run or modified.

**Result:** 10 confirmed findings, all P3. None of them breaks soundness or splits consensus on the deployed image (n2304-kmax4096, Rust backend, digest-pinned base image). Five findings are about the opt-in C backend or about hardening. Three are about documentation or comments drifting from the code.

**Does any finding depend on Task 9 (calibration)?** Only the gas-pricing question does, and it was refuted (see "Refuted"); Task 9 re-measures those rows anyway. No confirmed finding depends on Task 9. R4-C1 and R4-C2 need measurement runs of their own (C-backend arena peaks per set), which are separate from Task 9.

## Checked and sound

- **Never crashes or panics on any input.**
  - `stmt` has `forbid(unsafe_code)`. `decode_input` checks `5 ≤ len ≤ MAX_INPUT` and `n ≤ rest.len()` before `split_at` (stmt/src/lib.rs:943-953).
  - `parse` and `parse_multi` slice opTag and id with `n.min(32)` / `n.min(64)`, and take fixed offsets only after the exact `stmt_len` / `multi_len` check (lib.rs:532-547, 771-786). M comes from `built_legs` (≤ 8; `oversize` is refused at compile time, ffi lib.rs:28).
  - `parse_opening` uses `checked_add`, `checked_next_multiple_of` and `usize::try_from`, so wasm32 is safe (lib.rs:890-920).
  - pqz-ffi refuses native `panic = abort` (lib.rs:23-24). There are two `catch_unwind` layers (lib.rs:102-112, 157).
  - A Rust PQZL core panic is resumed on the caller after the Ctx is dropped (pqzl/rust.rs:86-90). Ligero catches its own panics (ligero.rs:499-504).
  - The C# `RowGas` guards `< 69` / `< 485` come before any slicing (PqzChainSpecEngineParameters.cs:141-152).
- **Length, MAX_INPUT and MAX_PROOF(id) are checked before any work.**
  - `pqz_precompile` reverts above MAX_INPUT before `from_raw_parts` (ffi lib.rs:150-154). `run()` (:99) and `decode_input` check it again.
  - `1 ≤ len(proof) ≤ max_proof(id)` is checked before dispatch (stmt lib.rs:961-966). The PQZL SV re-checks `rel_of` and MAX_PROOF before caches or hashing (sv.rs:1762-1766). Ligero checks `proof_len_ok` before parsing (ligero.rs:527).
  - Nethermind checks `PqzNative.MaxInput` (read from the library, `checked((int))` at start-up) before the P/Invoke (PqzPrecompile.cs:50, PqzPlugin.cs:61-62).
  - Largest inputs: n2304 411,525 B; n2560 493,445 B; n2816 394,117 B, all ≤ 524,288. The n2048 exception is documented (see "Refuted").
- **Retired ids and other sets' ids are refused.**
  - `parse` / `parse_multi` / `max_proof` / `built_legs` accept only `PQZL_ID` or `HAS_PQZH && PQZH_ID` (stmt lib.rs:141-154, 539, 767). n2816's zero PQZH_ID is refused.
  - `sets.rs ALL_IDS` equals every set.json, pqz_set.h and PqzSet.sol. The keccak of each label was recomputed and all 7 ids are distinct.
  - The tests `retired_ids_refused` and `other_sets_ids_refused` cover v2, v3 and PQZH v1. `pqzh_none::verify` returns `Ok(false)`, and lib.rs:42 asserts `!PQZH || HAS_PQZH`.
- **The result is 32 bytes, 0 or 1 only.**
  - Only VALID / INVALID are returned, plus the self-test hash for the exact input `06 00000000` (ffi lib.rs:103-106).
  - A panic gives …00 with status 3. A NodeFault writes nothing (lib.rs:146-165).
  - C# maps 0 to the output, 1 to a failed call, 3 to …00 and anything else to exit 120 (PqzPrecompile.cs:56-68). The Solidity callers accept only exactly word 1 (PqzCore.sol:622-623, UAPqzVerifier.sol:70-71).
- **Transcript and shape binding** (supports the invariants above).
  - PQZL: `SHAKE128("SCAAS-PQZ-TRANSCRIPT-V1"‖op‖be32(len)‖stmt)` over the exact decoded slice (rel.rs:165-172, sv.rs:1778).
  - PQZH: `keccak("SCAAS-PQZH-LIGERO-V1"‖op‖be32(len)‖stmt)`. The Ligero challenge order is root → challenges → polys → PoW → nonce → indices. Field elements are canonical and trailing bytes are refused (ligero.rs:540-554, fq.rs:228-233).
  - The decoder, both cores and RowGas agree on the op 1 R_TX/R_TX0 choice and on op 7 (M, auditorOn) from words 320 / 448. The (1, on) = (2, off) length collision is resolved by those words.
- **Gas per schedule row.**
  - The key is (op, be32 stmtLen, id = `input[37..69]`, M at 5+320, auditorOn at 5+448), the same bytes the decoder reads. `SmallWord` gives −1 for values ≥ 256.
  - A miss costs MinGas, returns …00 and makes no FFI call, so a row can only reject. Op 6 is the fixed `selftestGas`, with O(1) FFI work for any other op 6 input.
  - `Validate` refuses duplicates, op 6 rows, ids that are not 32 bytes, and gas ≤ 0. The gas sum is computed in `long`. A null schedule means `ulong.MaxValue` gas, which Nethermind's overflow check turns into out-of-gas.
  - All 26 provisional n2304 rows match `multi_len` / form lengths and the built legs.
- **Addresses.**
  - `0x…5caa0f01` / `0x…5caa0012` / `0x…5caa0013` (Addresses.cs:10-12) match spec §9.1. They are added together only while a schedule is active (PqzReleaseSpec.cs:25-33).
  - In the decompiled Nethermind 2.2.0, `ApplyToReleaseSpec` sets `ActiveSchedule` before the first `Precompiles` read. `ReleaseSpecDecorator` and `SystemSpec` (a MemberwiseClone) keep the same FrozenSet, and eth_simulate `MovePrecompile` builds no new set, so `ScheduleOf` cannot drop to null. The precompile result cache is keyed by spec reference.
- **Self-test and library hash pin.**
  - `ExpectedHash` for each set equals that set's `selftest.json`: [1,0,1,0], and [1,0,0,0] at n2816.
  - st[95] (the last message byte) is flipped for the negative vector (selftest.rs:106-117). A failure is a NodeFault and is not cached (:119-127).
  - The SHA-256 is checked before the first P/Invoke (PqzPlugin.cs:56-58). The static constructor only installs the resolver, and the check runs before `LoadGenesisBlock`.
  - The time-of-check to time-of-use window and the soname question are not new trust boundaries: an absolute-path dlopen matches by path or inode only, and swapping the file needs the same access as replacing the plugin dll.
  - The 1,634-point FFT KAT domain divides q − 1 at every set that has PQZH.
- **Arena and allocation bounds.**
  - The Rust Ctx uses `try_reserve_exact` (rust.rs:73). The C arena uses `try_reserve_exact`, and only `PQZ_ERR_ARENA` becomes a NodeFault (c.rs:128-148).
  - The PQZL coder and SV, and Ligero's `try_vec`, are sized from parameters and capped by MAX_PROOF (coder.rs:400-404, sv.rs:1270). The remaining infallible allocations (worker Box, mpsc, idx/leaves ≤ t, statement polys ≤ MAX_INPUT) are small and do not grow with the input.
  - The `on_worker` transmute is sound because the caller waits on `done.recv()` (pqzl.rs:93-104).
  - The C-backend sizing gaps are reported as R4-C1 and R4-C2.
- **Per-set constants** (all four sets, recomputed): q is prime and q ≡ 9 (mod 16); LOG2Q is 42 / 46 / 50 / 54; DELTA, MUX < 2^(LOG2Q+5), R64, ZETA⁴ = −1, IROOT, INV* and BARX = 2·LOG2Q + 4 are all correct. The SV CRT prime count is 4 / 4 / 5 / 5. `coeffs_ok` compares the full be8 u64 against Q.
