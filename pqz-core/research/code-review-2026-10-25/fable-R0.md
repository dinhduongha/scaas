### F-1 — P1 — R_TXM auditor copies of one group share key, randomness and coefficient index (= R0-1 / R0-C1)
`pqzl/src/pqz_rel.c:779-784` (build_debit, row 5): `evaleq (S, e++, T->pka, 2 * K + 2 * K * (j / 4), i, (int)(H.e2f + 1 + j), acc, -cval (T->va[j], i));` — for every leg j of a group the same `T->pka`, the same r slot `2K + 2K·(j/4)` and the same coefficient `i`. Spec row 5 (`docs/contracts/pq-zero-knowledge.md:962`, CTR-PQZ-26) says exactly that. Hence `v_{a,j}[i] − v_{a,k}[i] = Δ(d_{j,i} − d_{k,i}) + (e2_{a,j} − e2_{a,k})[i]`, |noise| ≤ 128 (‖e2‖₂ ≤ 64 proven per vector) ≪ Δ ≥ 2^26 − 1, so `round(centre(·)/Δ)` gives the digit difference exactly, to anyone with the statement or the stored blob, no key needed. Breaks receiver anonymity (decoy vs real leg) and amount confidentiality of audited op 7 with M ≥ 2, all four sets, PQZL and PQZH. Confirmed independently from spec + C code; the hint analysis (`pqz-anonymity.md:296`) counted these as 16 repeated hints and missed the direct cancellation. ### F-2 — P2 — z4 bimodal rejection under-sized for R_REG and R_DR / R_DA: Bprime = 1 is used as an ℓ2 bound of s[0] (= R0-C2)
`lnp-tbox-codegen.sage:141` `alpha4 = Bprime`, `:178` `stdev4 = gamma4 * sqrt(337) * alpha4`, `:335` `M4 = bim_gamma2M(gamma4)` — the codegen treats Bprime as the ℓ2 bound α4 of the filler vector `x = Ds·s1 + u` (√337 is the JL ℓ2 bound ‖R′x‖ ≤ √337‖x‖). `params/sets/*/reg_params.sage` and `dr_params.sage` set `Bprime = 1` with the comment "s[0], in [-1, 1]" (an ℓ∞ reading); `pqz_rel.c:515` (build_reg) and `:897` (build_dr) select `Ds = s[0]`, 64 CBD(1) coefficients of the secret key, ‖s[0]‖₂ ≈ 5.7 (≤ 8). Headers (`n2304-kmax4096/pqz_reg_params.h:38, pqz_dr_params.h:38`): stdev4 = 99.2, M4 = 1.0172703. Bimodal rejection (`lazer/rejection.c` `rej_bimodal`: accept iff u < 1/(M·exp(−⟨v,v⟩/2σ²)·cosh(⟨z,v⟩/σ²))) is exact only if ‖v‖² ≤ 2σ²·ln M = 2·9841·0.0171 ≈ 337, i.e. ‖v‖ ≤ 18.4 = √337·Bprime. The honest v = β4·R′·s[0] has E‖v‖² = 128·‖s[0]‖² ≈ 4096 (‖v‖ ≈ 64). The acceptance expression exceeds 1 for a large share of draws and is clipped, so z4 is not D_σ4: its distribution depends on R′·s[0] (R′ public per proof). Debit relations and R_DS are unaffected (Ds = e2, ‖e2‖₂ ≤ 64 = Bprime). Impact: a slow statistical leak of s[0] (64 coefficients of a long-lived key) across many proofs of the same key — R_REG is one proof per key, but R_DR (receiver) and especially R_DA (the auditor discloses often) repeat. No forgery. Fix: `Bprime = 8` (the hard ℓ2 bound of 64 ternary coefficients) in reg / dr specs via `gen_set.py` → stdev4 1.55·2^9, +96 B per proof; add a codegen/gen_set assertion that every filler's Bprime is an ℓ2 bound; fix the "[-1, 1]" comments; part of the id bump.

### F-3 — P3 — the final challenge is never filtered to ‖c‖ ≤ η; the headers' knowledge error assumes it (= R0-C3)
`lazer/intvec.c:598-620` `_intvec_urandom_autostable`: 32 coefficients uniform in [−8, 8], mirrored, no norm test; callers `lnp-quad.c:245/:494`, `abdlop.c:358/:517`, Rust `quad.rs:142/:306`, `sv.rs:1743`; `params->eta` is not read anywhere. The codegen's |C| = 2^130.79 and `e_s0_set.py` part 3a (`P(accept) = 0.9929`) both count only the η-filtered set, and the MSIS bound `B = 4η√(B1²+B2²)` in every "knowledge error ≤ 2^-127 under MSIS(…)" line uses η = 140. Since √‖σ₋₁(c)c‖₁ ≥ max_j|c(ζ_j)|, at least 0.71 % of sampled challenges violate the hypothesis. No attack follows (the extractor's bound grows by at most (η + η_max)/(2η) where η_max ≤ ‖c‖₁ ≤ 504, and a cheater cannot choose c), but the stated figure is not a theorem about the implemented protocol. Fix (either): resample c from (cseed, counter) until the η test passes, identically in prover and all four verifiers, in the id bump; or recompute B with η′ = the 2^-128 quantile of √‖σ₋₁(c)c‖₁ and re-run e_s1, and make e_s0 R4 charge Pr[c ∉ C_η] or count |C| unfiltered.

## R0-1 fix design (direction 2, `R0-1-auditor-shared-randomness.md`)

**Verdict: sound in principle and sufficient for the leak found; four required changes / caveats.**

Does it remove the leak? Yes. The cancellation needs two auditor copies with the same (key, r_g, coefficient) triple. With leg j of a group of s legs at window [16·(j mod s), +16) of one `pk_aᵀ r_g` (s ≤ 4 fits d = 64), every auditor copy in a group has its own coefficient, so `v_{a,j} − v_{a,k}` is Δ(d_j − d_k) plus an MLWE-type mask ⟨row_{c_j} − row_{c_k} of pk_a's negacyclic matrix, r_g⟩ — the ordinary LPR / Kyber situation (all d coefficients of one `pk·r` carry message). Row 5 keeps the same digit bits as row 3, so recipient and auditor copies still encrypt the same amount; the coefficient shift is an `X^{-c}` factor in the evaleq (`mul_xinv`), no soundness change; statement, calldata, blob and e2 blocks are unchanged.

New leaks examined:
- Auditor copy vs recipient copy of the same leg (`v_j − v_{a,j}`): d cancels but the masks are under different keys (pk_j vs pk_a) → masked; the recipient learns an LWE sample under the honest auditor key (not a hint); same as today. None.
- Across groups: independent (r_g, e1_g); the auditor's hints count per group. None.
- With the sender's v_f: `v_f` is under pk_f in window 0 of group 0; masked unless pk_f = pk_a (F-4). The sender knows r anyway, so v_f adds no adversarial hint. None beyond F-4.
- Auditor UA as recipient or sender: F-4 — a leak before and after the fix, needs a contract rule (or auditor windows that avoid window 0, only possible for s ≤ 3).
- **Auditor disclosure path (R_DR kind AUDITOR, "R_DA"): required change not in the note.** `pqz_rel.c:883-905` build_dr proves `(uᵀ s)_i + e′_i + Δ d_i − v_i = 0` at coefficient i; after direction 2 the auditor copy of leg j decrypts at coefficient `16·(j mod s_aud) + i`. The relation needs the offset as a public input, and the disclosure statement (`pq-zero-knowledge.md:1173-1186`: opTag … amount, kind, pk, u, v — no leg word; `stmt/src/lib.rs:84`) has nowhere to carry it: add a word (or fold the offset into `kind`), change `pqz-stmt`, `PqzCore.disclosureStatement`, both provers / verifiers and the vectors. SENDER_S / RECEIVER_X are unchanged (window 0). The offset reveals j mod s, which is public already.
- Group mapping: `g(j) = ⌊j / s_aud⌋` with the auditor on, ⌊j / 4⌋ off, must change together in `pqz_rel.c` shape_of (`PQZ_TXM_GROUPS`, `pqz.h:94`), `stmt/src/lib.rs:656`, `PqzCore._legOf`, `cs.rs`, `sv.rs`, the Enc group seeds (CTR-PQZ-19) and the auditor's Dec (coefficient `16(j mod s)+i`). New R_TXM shapes (n2304 M = 4 → G = 2, M = 8 → G = 3; n2048 M = 4 → 2, M = 8 → 4) mean new codegen specs, e-s1 and e-s0 runs and proof sizes (+2K polys in s1 per extra group; check `MAX_PROOF` 98,304 — n2816 is unchanged at s = 4).
- Spec text to rewrite: §4.5 "16 coefficients per recipient", CTR-PQZ-26 row 5 and "G = ⌈M/4⌉", `pqz-anonymity.md` §8.2 "16·M + 16", CTR-PQZ-03 / -04 exception figures (F-6).

Is 32·s the right worst-case hint count? Yes under the model: each malicious recipient key yields 16 forms `(e_jᵀ r_g − s_jᵀ e1_g)[i]`; the auditor's copies now yield 16 distinct forms per leg instead of one repeated set, so 16s + 16s = 32s with the auditor, 16s without; v_f adds none (the sender holds r); hints do not accumulate across transfers (fresh r per operation). The study's reproduction of all four 80-hint values and of the n2560 128-hint record is good evidence the script is the old model with the count changed.

Is the hint model a sound basis for 450? DDGR20 worst-case mixed forms with V_max = var_s·β_e² + var_e·β_s², perfect hints, Hadamard bound on the volume — conservative for the primal attack, fine. The **dual_hybrid − offset** column is not a tool result: lattice-estimator has no hints, so the study runs `LWE.dual_hybrid` on LWE(n − h) and subtracts the primal offset (uSVP(n − h) − DDGR20 mixed β at h) [estimate]. The s decisions rest on it: at n2304 the raw dual_hybrid(n − 128) is exactly 450 and the −6.79 offset makes s = 4 fail (443.21 / 445.21); s = 3 passes by 3.0 / 6.0 β (`hints-s.txt` lines 57-58). The direction of the heuristic is conservative and the chosen s is the smaller one, so I accept it, but SET.md / CTR-PQZ-04 should state that s_aud at n2304 rests on a heuristic with a 3-β margin and that no hinted dual estimate exists. The DDGR20 side is clear at every chosen s (n2304 s = 3: 463.04; n2560 / n2816 s = 4: 467.60 / 483.09; n2048 s = 2: 451.92 ≥ 450 primal, dual ≈ 444 under the widened exception). Owner rulings (s only with the auditor; 4 without; n2048 exception ≈ 444) are internally consistent: the 64-hint instance is the same with the auditor at s = 2 and without at s = 4.
