## Independent findings

### C0-F1 — P0 — classical Zether: every auditor copy of a multi-recipient transfer is ElGamal under the same key with the same randomness; the mask cancels (= Codex C0-1 / C1-1)

`docs/contracts/zether.md:551` defines `C_aud_j = [v_j]G + [s]Y_a` with one `s` per transfer; `ZetherVerifier.sol:542-546` fixes `l.ya = Y_a`, `l.zs = z_s` once for all legs and `:562` checks E6_j `[z_vj]G + [z_s]Y_a − [c]C_aud_j − A_aud_j` with that shared `z_s`, so any accepted proof has `C_aud_j − C_aud_k = [v_j − v_k]G` for every pair of legs. The `C_aud_j` are in the statement (`ZetherLib.sol:593`), hence in calldata on every storage mode, in `R` on BUNDLE and in `TransferBundles` on HASH. Consequences, with no key and no broken proof: (a) two decoys (v = 0) have byte-identical `C_aud`; (b) with one real leg the oriented difference `C_aud_real − C_aud_decoy = [v]G` has a 64-bit discrete log (the amount is range-proven `< 2^64`), found by BSGS/kangaroo in ≈ 2^32 group operations, which also tells which leg is real (the other orientation has no solution below 2^64); (c) one known amount (the recipient's own, or one `AUDITOR` opening of leg `k`) gives `[s]Y_a = C_aud_k − [v_k]G` and so `[v_j]G` for every leg. This breaks receiver anonymity of audited multi-recipient transfers (the whole point of the decoys, CTR-ZTH-37) and amount confidentiality (P0 per the brief), and makes the `AUDITOR` disclosure kind open more than one leg. It is exactly the structure of PQZ R0-1 (same key, same `r_g`, two messages), which part 1 fixed with distinct coefficient windows; ElGamal has one "coefficient", so that fix has no literal analogue. Single-recipient transfers (one `C_aud` per `s`), `C_out_j` (distinct keys `Y_tj`) and `C_deb` are not affected; CTR-ZTH-30's salt already prevents the same cancellation *across* transfers, which shows the mechanism was understood for the retry case but missed inside one transfer. Not in the 2026-10-19 rows T / U / V1 / V2 / V3 / T2. Nothing is deployed (dev chains only, `ZetherSafety`).

Fix (owner to choose; both need a new `proofSystemIdMulti`, prover, vectors, spec §11 and CTR-ZTH-40): **(i)** per-leg auditor key derivation under the shared `s`: `C_aud_j = [v_j]G + [s]·([h_j]Y_a)` with a public `h_j = hashToScalar("SCAAS-ZETHER-AUD-LEG-V1" ‖ j)` (or any fixed public non-zero per-leg scalar); E6_j becomes `[z_vj]G + [z_s·h_j]Y_a − [c]C_aud_j − A_aud_j` (one extra `mulmod`, no new point, statement and proof sizes unchanged); the auditor decrypts leg `j` with `x_a·h_j`; security of the tuple `(G, [s]G, Y_a, [s·h_j]Y_a, [s·h_k]Y_a, …)` is one DDH instance since every element is a public function of `[s]Y_a` — the ElGamal counterpart of direction 2. **(ii)** independent `s_j` per auditor copy with its own `D_aud_j = [s_j]G`, `A_D,j` and `z_sj` (+1 statement point, +1 commitment and +1 scalar per leg). Interim containment: refuse audited multi-recipient transfers with `M ≥ 2` (`_auditorPoint` with `nOff == 0 && m > 1`), or set `auditorMode = NONE` on every Zether token until the id bump.

### C0-F2 — P3 — PQZ spec says the fee beneficiary needs no PQZ key; the code requires one

`pq-zero-knowledge.md:1319-1320`: "fees go to the beneficiary's public UA-ledger balance (CTR-PQZ-06), which needs no PQZ key." `PqzCore.sol:729-732` `_common`: `if (o.ben != 0) { if (!_registered(e.registry, o.ben)) revert AccountNotRegistered(o.ben); …}` with `_registered` (`:856-859`) = `recordOf(ua).pqzKey ≠ 0`. A signing UA without a PQZ key cannot be a beneficiary (the relayer that holds only an `mldsa65` UA must register a PQZ key it never uses). Not a security defect; a doc/code mismatch to rule one way (the code's rule is the stricter one). Fix: one sentence in §7.10 / CTR-PQZ-06, or `_registered` → `kindOf(ua) ≠ 0` for the beneficiary.

### C0-F3 — P3 — `mtxPrepareAcc` relayability contradicts itself across the documents (= agy C0-3, narrowed)

`pq-zero-knowledge.md:1153`: "`mtxPrepareAcc` … is not an allowlisted envelope op." `PqzLayer.sol:325-333` `_isPqzOp` lists it with `mtxRollOver` ("relayed, owner 2026-10-20; the fee may be 0"), `metatx.md:328` and `:346` list both. Fix: correct §7.6 and reword the NatSpec.

## Checked and sound

- **PQZ statement binding.** `PqzCore._header` (`:875-880`): `opTag, psid, chainId, token, registry, from, to / recipientsHash, ben, fee, amount, recipient, sendCounter, p, validUntil, auditorOn, shieldIn, chainUid, binding, salt, memoHash`; keys from the registry pointers (`_key`, `:891-894`), `T` rebuilt from state (`_total`), `out` from calldata. `_bindMode` (`:216-218`) folds the storage mode into the binding on both paths (D15 / W-A); the burn has no mode and keeps the envelope binding. `authDigest` over the same statement (`_check :813-816`), so `authSig` covers the envelope. No relayer-swappable field found.
- **Race-freedom of PQZ debits.** `_total` (`:741-760`) rebuilds `acc ± Σ pending[window)` + `Trivial(shieldIn)`; a rollover between prove and submit moves entries from the window into `acc` (or past `p`, then subtracted) — the same `T` by associativity; `unitsOf` is invariant for the same reason; slots survive because rollovers delete only below `rolled − INLINE_MAX` and `PendingRange` needs `p ≥ floor` (`PqzStateLib.sol:99-105`); `ROLL_AGE` (`:795`) keeps entries newer than the proof out of rollovers; a same-block TRIVIAL merge touches only index `≥ max(floor, rolled)` (`:345-346`). Residuals as documented (`InlineTooFar`, own-block merge).
- **Balance conservation (PQZ).** `_debit :840` `totalShielded += shieldIn − fee − amount` (checked arithmetic), `_pay` (`PqzLayer.sol:286-294`) moves exactly `shieldIn` in and `fee − M·d` + `M·d` out of `SHIELD_POOL`; shield `+amount` within `maxShielded`; fee = 0 and `d = 0` are the no-op branches. **(Zether)** `_debit :668-673` `acc_f −= (C_deb + [fee]G, D_out)`, `_payFee :658` `totalShielded −= fee` with `fee = txFee + M·d` in the statement word read by E5 (`FEE_AT = 288`), the layer pays the same from the pool (`ZetherLayer.sol:241-250`); unshield `acc_f.C −= [amount + fee]G` with `amount ≤ 2^54`, `fee < 2^64`, no alias mod `r`; shield `pending.C += [amount]G`.
- **Zether Σ-protocol and Fiat–Shamir.** Statement (all header words and points) absorbed first, then every commitment, then `c` (`_ctx :412-423`); E1–E8 as `zether.md` §8 / §11, `z_v` shared by E3 / E4 / E7 (the Σ-Bullets link), `Σ z_vj` in E4; range proofs on the running transcript; scalars `< r`, challenges `≠ 0`, every statement and proof point passes through a G1MSM (subgroup check, `G1Bls12381.msm`); `accSeq` / `sendCounter` checked before verification (`_checkSeqs`), the mode in `opTag`, relay binding in the header. Soundness of `b′ + Σ v_j + fee < 18·2^64 ≪ r` as CTR-ZTH-18. Apart from C0-F1 no defect.
- **Zether disclosure.** `ZetherDisclosure.sol:34-67`: challenge binds `chainid, chainUid, token, entryRef, index, amount, kind, A1, A2`; `amount < 2^64` gives one valid amount per `[amount]G`; the three DLEQ pairs prove exactly `v_j = amount` for leg `j`; `SENDER_S` opening every leg is documented and accepted (CTR-ZTH-37 / -40); `AUDITOR` isolation fails only through C0-F1.
- **PQZ disclosure.** `disclosureBuffer` (`PqzCore.sol:606-666`): `pk` from the registry (never the opening), `u_{g(j)}`, `v_j` / `v_{a,j}` from the op blob, `kind + 256·(j mod S_AUD)` for the auditor window (R0-1 follow-up present), `amount < 2^64`, `kind ≤ 2`, `AUDITOR` refused without copies; `(pk_j, v_j)` identifies the leg since recipients are pairwise distinct. Nothing reveals `r` or noise.
- **Privacy versus the spec.** PQZ: sender, candidate recipients (`recipients` in the event, `Credited` per leg), counts, `p`, fees and shields are public by design; legs are credited and consumed as a prefix (`_creditLegs`, `_window`), decoy fee uniform, the auditor is no party when copies are on (`_noAuditorParty :233-235`, F-4 fix present), `S_AUD` groups 2 / 3 / 4 / 4 as `PqzSet.S_AUD` (`_groups`, `_groupOf`), consistent in credit offsets, `_bundleShape` and the disclosure window. Zether: C0-F1 is the gap; otherwise `C_out_j` under distinct keys and `D_out` shared are standard multi-recipient ElGamal (DDH with independent keys).
- **Domain separation.** PQZ: `OP_*` tags per relation, `psid`, chain, token, registry, `chainUid` in every statement; `authDigest` tag; `entryRef` tag with chain / token; UA `ua_msg = H(MSG_TAG ‖ TAG(kind) ‖ purpose ‖ digest)` (`UAKinds.sol:209-211`), purposes `zether-auth` / `zether-owner` / `pop` distinct; `popDigest` binds chain key, `chainUid`, registry, UA, `pqzKeyHash` (`:220-224`); `uaAuthDomainSeparator` carries the generation (`:226-232`). Zether: op tags with the mode, `psid` (`/multi` variant), `ZTX_V1_*` tags, envelope tags for the two relay paths (`ZetherLayer.sol:272, :291`), `chainUid` in every digest (CTR-ZTH-36). No cross-token / cross-chain / cross-generation replay found.
- **PQ signature choices (design level).** ML-DSA-44 / 65 and SLH-DSA-128s sign `M' = 0x00 ‖ 0x00 ‖ pq_msg` (pure mode, empty context, `PqUA.sol:44-46`), FN-DSA-512 the 32-byte `ua_msg` (EIP-8052 convention); kind tags in `pq_msg` prevent cross-kind reuse.
