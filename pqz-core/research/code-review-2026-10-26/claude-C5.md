## Checked and sound

- **Envelope signature coverage, address path.** `MetaTxLib.hashStruct` (`common/MetaTxLib.sol:97-102, :129-134`) hashes from, `keccak256(data)` (selector and args) or to/value/entryRef, batch, nonce, validUntil, mode, fee, and canon(relayer) / canon(feeRecipient). The type strings match the field order for all four structs, ReceiverFee (`MetaTokenBase.sol:33-34, :309-313`) and the trade structs (`TradeLib.sol:17-63`). The domain (`SaltedEIP712.sol:36-69`) is name, "1", live chainid, verifyingContract = the clone, salt = CHAIN_UID ≠ 0. It is rebuilt per clone and on a chainid change; ERC-5267 fields are 0x1f.
- **Envelope coverage, UA path.** UAMetaTransaction and UAMetaTransfer have their own typehashes (`MetaTxLib.sol:167-204`). A derived id is authorised by `requireAuthorized` with a distinct purpose (METATX, TRADE, RECEIVER_FEE, METATX_CANCEL; `UARegistry.sol:545`). A native id signs the typed digest, and every reachable digest has a distinct typehash, so there is no cross-purpose or cross-path reuse. Native UA_POOL and SHIELD_POOL are refused (`ERC20MetaTx.sol:453-454`); 0 is covered by C5-C2.
- **Nonce, replay and cancel.** One bytes32-keyed map serves every path (`MetaTxBase.sol:45-47`). `_checkEnvelope` checks the relayer, inclusive expiry, unknown mode bits, fee nibble ≤ 2, the exact nonce and from ≠ this before the signature (`:161-174`). The nonce is consumed before the self-call, and any later failure reverts it. Pay lanes use nonce 0 on `payLane(payId)`. `uaCancelNonce` refuses native ids and is single-use per digest, which matches `accounts.md:257` (`ERC20MetaTx.sol:87-91, :340-350`). V3-02 (a cancel not bound to its nonce) is unchanged and recorded (`decisions.md:3337`).
- **Allowlist and fee classes (`MtxRule`).** `_checkCall` (`MetaTxBase.sol:191-206`) refuses unlisted selectors and enforces the exact staticLen: wrap 36/68, unwrap 100/132, addReserve 68, wrapToUA 100, unwrapToUA 132, burn 36, cancelNonce 36, PQZ 68/100. The AMOUNT basis `mload(data+36+32i)` is argument i and is read only after a length check. ABSOLUTE+PERCENT is refused. `_mtxRule` and `mtxSelectors()` agree for every kind. `_uaAllowed` is a strict subset (burn and unwraps; no cancelNonce, approve, transfer, admin, mint or mtx*).
- **Fee cannot be redirected or doubled.** `_callFee` (`ERC20MetaTx.sol:242-252`) takes the signed amount uncapped only for ABSOLUTE+FIXED; everything else goes through `FeePolicy.compute`, capped at 1 % with mulDiv (`FeePolicy.sol:32-52`). The fee is charged once per envelope, after the call (address path `_transfer`, UA path `_uaMove`). The token, UA_POOL and SHIELD_POOL are refused as recipients (`:250`, `_update:279-281`, `_uaMove:477-479`, `_poolMove:487`). The payee is refused as fee recipient on the typed paths (CTR-MTX-08). An unbound recipient follows submitter normalization (see C5-C8 for the wording).
- **Relayer griefing.** `MODE_RESTRICT_RELAYER` is checked against msg.sender on every path, batches included. An inner OOG reverts everything, so no nonce is burnt. ERC-1271 has the 64/63 + 5000 starvation revert (`SigCheck.sol:62-63`). ERC165Checker and sendValue fail closed. No try/catch exists in scope.
- **Inner-call reentrancy and return handling.** `nonReentrant` admits only msg.sender == this with ticket 1 and consumes it (`MetaTxBase.sol:57-67`). `_selfCall` fails closed when the target did not consume the ticket, bubbles revert data and clears SENDER and TICKET (`:213-224`). `_msgSender`, `_ticketSubject` and `_ticketBinding` are trusted only under a live ticket (`:276-295`). The only other `this.` call is a view (`PqzLayer.sol:144`). Legs cannot be the token itself (`UnderlyingLib.sol:111`). The binding slot is always non-zero on confidential kinds, so batch items never read a stale binding. PQZ ops cannot be batched. V3-04f is fixed: pay, mint, role, owner, rate and guardian functions are nonReentrant.
- **Batches.** All four batch functions are atomic, refuse empty or length-mismatched input, and give each item a fresh ticket; `_requireBatchable` runs before each item (`MetaTxBase.sol:116-127`, `ERC20MetaTx.sol:307-336`).
- **Named builders.** `mtxTransfer`, `mtxTransferWithFee`, `mtxExecuteWithFee`, `mtxPay`, `uaTransfer`, `uaTransferWithFee`, `uaPay` and `uaUnwrap` build the same struct as the generic path. Their shape checks (`_requireFeeShape`, `MetaTokenBase.sol:364-371`) match `metatx.md:603-619` and `accounts.md:687-691`, and `IMetaTokenV2.sol:26-33, :61` declares them.
- **Direct payments.** `payWithFee` caps PERCENT at 10,000 ppm and FIXED at 1 % of amount, requires a non-zero recipient unless the mode is NONE, and refuses a fee to the payee. `payWithFeeToUA`'s missing payee check is vacuous, because the derived payee can never equal `pad(feeRecipient)`. Both are direct-only (on no allowlist). The events match CTR-MTX-08 and CTR-UA-28 (`MetaTokenBase.sol:375-405`).
- **Receiver-pays.** The payer intent must have a bound relayer, fee NONE, `payLane` at nonce 0, and entryRef ≠ 0. The payee co-signs ReceiverFee over the payer's single-use digest, with 0 < fee ≤ value and a recipient that is not the payee, the token or UA_POOL (`MetaTokenBase.sol:317-361`).
- **Signature checks.** OZ `tryRecover` accepts 65 bytes only, enforces low-s and never accepts 0. ERC-1271 uses a capped staticcall with exactly 32 bytes of return and a word-exact magic. An EIP-7702 designator counts as an EOA on the address path and as ECDSA then the delegate's ERC-1271 on the UA path (CTR-UA-24). The SmartKeyAccount clone codehash is the EIP-1167 runtime (`SigCheck.sol:26-70`, `MetaTokenBase.sol:62-63`).
- **Token base balances, allowances and the UA ledger.** `_poolMove` keeps `balanceOf(UA_POOL)` equal to the sum of derived balances. A UA_POOL debit in `_update` needs a derived ticket subject (`ERC20MetaTx.sol:278-289, :484-502`). UA_POOL can never get an allowance, because approve is on no UA allowlist and there is no permit. `transferToUA` as a direct entry point has a derived SIGNING receiver and a native sender.
- **Wrapping and unwrapping with outside ERC-20s.** `_pull` prices the measured delta (fee-on-transfer in) after a shortfall check (`UnderlyingLib.sol:156-172`). SafeERC20 handles false returns. `payOut` / `payOutToUA` require an exact balance drop, so fee-on-transfer out reverts (`:262-292`). Burn and reserve debit happen before the one outside call (CEI). The native leg needs value == amount, and a relayed native wrap is impossible. `mtxWrap` / `uaWrap` require received == o.amount, receiveToken == this, and a fee within the signed ppm (`:180-230`, `TradeLib.sol:83-136`). Rounding (floor, floor, ceil) keeps Σ⌊reserve·q⌋ ≥ supply. V3-04e is fixed: events emit `minted − fee` (`UnderlyingToken.sol:108, :125`).
- **Guardian and rate path (CTR-TOK-06/07/13).** `disableWrap` is one-way and gated by role and flag. propose, cancel and execute are rateAdmin-only, with one pending change and an exact integer step bound. A pending change pauses every wrap path. `executeRate` checks every leg's balance ≥ reserve and the collateral at the new rate, and `RateDecreaseWithDisabledLeg` applies. `disableFeature(RATE_ADJUSTABLE)` drops a pending change (`UnderlyingLib.sol:311-404`).
- **Admin roles and pause.** AdminLib validates flags per kind and refuses REGULATED flags (PAUSE, FREEZE, FORCE, ALLOWLIST) as not built, so the `_uaMove` hook bypass cannot skip a live pause. PAYABLE and BURNABLE are always locked. Roles exist only for set flags, rateAdmin must be a contract, ownership transfer is two-step, renounce clears the pending owner, and library functions are delegatecall-only (`AdminLib.sol:77-209`). No admin function is allowlisted.
- **Initialisation.** The implementation locks itself in its constructor (`MetaTokenBase.sol:65`). `initialize` is factory-only, runs once and checks the registry chainUid (`:70-82`). `NoUnderlyingToken._init` refuses legs, rate and conf, and the initial mint refuses 0, the clone, UA_POOL and SHIELD_POOL. `UnderlyingLib.initToken` requires 1-8 legs, no duplicates, legs with code that are not the token, decimals ≤ 255 from an exact 32-byte return, 0 < num, den < 2^96, and rate bounds of 2-30 d and 1-1000 bps. `_requireUnused` covers every ConfidentialConfig field.
- **Factory: publishEnv, deployImplementation and createToken.** Only the registrar can publish, deploy, deprecate or enable kinds. An env is write-once and must name this factory and chainUid, with empty or zero lib pins refused (`OpenFactory.sol:261-277`). Library code hashes are checked at deploy. That they are not compared with the init code's link references is an owner ruling (`token-wrappers.md:705-726`) and is not reported. Releases are append-only, version 0 is refused, and kind(), factory() and chainUid() must give exact 32-byte answers (`:93-111, :306-315`). Deprecation is one-way, the notice period is capped at 30 days, and confidential kinds start disabled. The clone salt is creator-scoped and the predicted address must have no code and not be indexed. The clone is initialised in the same call. The unregistered route allows only plain kinds as version 0, which the DEX treats as OUTSIDE (`SCaaSDex.sol:194-200`). Release gas against 2^24 regular gas is asserted; the state-gas side is C5-C1.
- **Storage layout pins.** The ERC-7201 constants `scaas.metatx`, `scaas.ua.ledger`, `scaas.token`, `scaas.underlying` and `scaas.trade`, and the transient `scaas.mtx.guard/sender/ticket/binding` literals, were recomputed with `cast keccak` and match the source (`MetaTxBase.sol:36-50`, `ERC20MetaTx.sol:42`, `AdminLib.sol:65`, `UnderlyingLib.sol:64`, `TradeLib.sol:46`).
- **SSTORE2 pointer handling.** The init code `61 LLLL 80 600c 6000 39 6000 f3` is 12 bytes and returns `0x00‖data`. Length is capped at 0xfffe, a failed CREATE reverts, `read` skips the STOP byte and returns empty for a pointer without code, and callers in scope read only pointers taken from contract state (`SSTORE2.sol:11-29`).
- **Assembly memory safety.** `_checkCall`'s mload is in bounds. `_selfCall` and the `_deploy` revert bubbling use returned data at the free pointer. `SigCheck._erc1271` writes only scratch slot 0. The TradeOrder / UATradeOrder memory alias has the same 13-word layout (`ITradeToken.sol:11-44`).
- **Unbounded loops.** Batches are bounded by the caller's own transaction gas, legs are ≤ 8, factory index arrays are read by index only, and env lib loops are registrar-only.
- **NET-EVM-02/05/06 cross-check.** chain_uid domain separation and the factory's chainUid / ChainUidMismatch checks are consistent with the specs. NET-EVM-06's deploy-gas statement is C5-C1.
