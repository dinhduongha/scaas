# PQZH — the hash-based proof system

PQZH is one of PQZ's two proof systems (the other is [PQZL](../pqzl/README.md)). It proves the same statements as
PQZL, but its security rests on hash functions only (Keccak-256), not on lattice problems. That makes it the
conservative choice: if the lattice assumptions behind PQZL were ever weakened, PQZH would still hold. The price is
size: at the default set `n2304-kmax4096` an `R_TX` proof is at most 251,608 B (the crate's exact bound, `ligero_kat
sizes`) against PQZL's 46,670 B (both: `../params/sets/README.md`). Verify times wait on the calibration of plan
5h Task 9 (the backend study's figures are history: [pqzh-ligero.md](../../docs/research/pqzh-ligero.md)). The same
`PQZ` precompile accepts both; the `proofSystemId` inside each statement says which system made the proof. PQZH
exists at three of the four parameter sets (not at `n2816-kmax65536`). Unaudited, not for production funds.

PQZH uses **Ligero** over the field F_q (q of the parameter set, the same q as the encryption: 2^42 − 215 at
`n2048-kmax1024`, 61,275,424,977,257 at `n2304-kmax4096`, 2^50 − 42,310,535 at `n2560-kmax16384`), with evaluation
domains over small radices of q − 1 (431 and others, per set), a Keccak-256 Merkle tree and transcript, and zero knowledge. It is written in Rust. For the big picture read
the parent [pqz-core/README.md](../README.md) first; the design and every measurement are in
[pqzh-ligero.md](../../docs/research/pqzh-ligero.md).

## The Ligero crate (`ligero/`)

- **Relations:** `R_REG`, `R_TX`, `R_TX0`, `R_BURN`, `R_DS`, `R_DR` and the multi-recipient transfer `R_TXM` (op 7)
  for M = 1, 2 and 4 (pqz-stmt `built_legs`, owner ruling D20). M = 8 is not built: with the auditor its proof bound
  (368,328 / 340,168 / 375,148 B at `n2048-kmax1024` / `n2304-kmax4096` / `n2560-kmax16384`) exceeds every set's
  `MAX_PROOF_PQZH` of 327,680 B (`../params/sets/README.md`).
- **Parameters:** one fixed preset per parameter set, `Params::proven()`: at `n2048-kmax1024` n = 32,756, k = 817,
  t = 121, 127.23 bits of proven (unique-decoding) soundness; the other sets below. Parameters are fixed per `proofSystemId` and op, never read
  from the proof.
- **Statements** are decoded by the shared codec `pqz-stmt`, so the same canonical rules apply as everywhere else.
- **Parameter sets** (owner 2026-10-21, plan 5h Task 8c): one set per build, as PQZL — feature `set-<set>`
  (`set-n2048-kmax1024`, `set-n2304-kmax4096`, `set-n2560-kmax16384`), at most one; none = n2048-kmax1024;
  `pqz-ffi` forwards its set (part 2). The constants come from `pqz-core/params/sets/<set>/rust/set.rs` (PQZL's, with
  pqz-stmt's `MAX_PROOF_PQZH` / `MAX_INPUT`) and `pqzh_set.rs` (generator, F_q^4 non-residue, radices, preset), both
  generated by `params/sets/gen_set.py` from the set's `set.toml` (`[pqzh_preset]`). **n2560-kmax16384**: THE preset's
  n / k with t = 122 (127.55 bits; owner 2026-10-23; debit bounds 303,412–305,120). n2048-kmax1024 keeps THE preset;
  **n2304-kmax4096 uses preset B** (owner 2026-10-22: radices 2 / 7 / 17 / 19 / 43 / 431, n = 45,752, k = 952,
  t = 120, 127.40 bits; debit proof bounds 251,608–252,328 B, and 296,248 B for the audited R_TXM M = 4 since the R0
  review fix). `MAX_PROOF_PQZH` is 327,680 B at all three sets (owner
  2026-10-23 for n2560-kmax16384, 2026-10-25 for the other two: the R0 review fix's audited R_TXM M = 4 in two
  groups, bound 279,756 / 296,248 B; it was 262,144 B there). n2304-kmax4096's fallback A is kept, never in a production
  build: feature `fallback-retry` (THE preset, the prover re-proves until the proof fits;
  `docs/research/pqzh-set-a-proof-limit.md`). History: at the 8c change the n2048-kmax1024 proofs stayed
  byte-identical. What a chain needs to run PQZH at a set: `params/sets/<set>/PQZH.md`.
- **Dependencies:** `sha3` and `pqz-stmt` only.
- **Two builds:**
  - the default feature `bench` adds the reference presets, the float parameter model, soundness accounting and the
    test client — for research and tests;
  - the production build is `--no-default-features`: only the proven preset, no floating point (a clippy lint
    enforces it). `pqz-ffi` uses this build.
  - Feature `oversize` (bench only) also builds op 7 at M = 8 and 16, above `MAX_PROOF`.

## Build and test

Run from `pqz-core/`:

```sh
(cd pqzh/ligero && cargo test --release --offline)                        # all tests, with the bench feature
(cd pqzh/ligero && cargo test --release --offline --no-default-features)  # the production build
(cd pqzh/ligero && cargo test --release --offline --features set-n2304-kmax4096)  # another parameter set
scripts/capped pqz-core/pqzh/ligero/runs/c8.sh <tag> <set>      # from the repository root: one set's round
scripts/capped pqz-core/pqzh/ligero/runs/c8b.sh            # from the repository root: n2048-kmax1024 + n2304-kmax4096 + fallback A rounds
scripts/capped pqz-core/pqzh/ligero/runs/gateb.sh <tag>   # from the repository root: the gate-B round
scripts/capped pqz-core/pqzh/xcheck/ligero.sh             # from the repository root: Rust bytes = C bytes, all six forms
scripts/capped pqz-core/pqzh/ligero/runs/ct.sh <label>    # from the repository root: the constant-time check (x86-64)
```

**Prover hygiene (review round 2, 2026-10-19).** The prover keeps no branch, table address or 64-bit division on
secret values (witness, `rnd32`, masks): `runs/ct.sh` builds the test-only feature `ctgrind`, proves all twelve
relations with the witness and `rnd32` marked secret under valgrind memcheck and must report nothing; the inventory,
the declassified points and the wasm32 code check are in
[O-pqzh-constant-time.md](../research/code-review-2026-10-19/O-pqzh-constant-time.md). Every secret buffer is wiped
on every exit (best effort, the platform boundary is stated there). The library is `#![forbid(unsafe_code)]` (only the
test-only `ctgrind` build has the two memcheck client requests). The verifier reserves its parameter-sized buffers
fallibly: `try_verify` returns `Err(Oom)`, which `pqz-ffi` reports as a node fault.

## Why Ligero (and not the STARK in `stark-backup/`)

Three backends were measured on the same `R_TX` statement (history: the first parameters, today `n2048-kmax1024`),
all zero knowledge with 128-bit proven security
([pqzh-backend-comparison.md](../../docs/research/pqzh-backend-comparison.md)):

| Backend | Proof | Prove | Prover memory | Verify p99 | Outcome |
|---|---|---|---|---|---|
| **Ligero over F_q** (`ligero/`) | ≈ 231 KB | 0.65 s | 43 MB | 10.5 ms | **chosen** |
| STARK (Plonky3, FRI + ZK, Goldilocks⁵) | 622 KB | 20.4 s | 2.8 GB | 19.1 ms | rejected |
| ZK WHIR (Plonky3 WHIR with hiding) | 1.95 MB | 43 s | 2.4 GB | 46.5 ms | rejected (reaches only ≈ 124 bits) |

`stark-backup/` keeps the STARK crate (`src/`: AIR, encryption, relations, the ZK WHIR adapter `whirpcs.rs`), its
runs, the Solidity and StarkEx cost models (`sol/`) and the design-study counts (`pqzh_count.py`, `counts.txt`).

## Status and open points

- Gate B passed on 2026-10-17 with the PQZH `proofSystemId`
  `keccak256("scaas/pqz/pqzh/ligero-fq-r431-keccak256-zk-proven/v1")` = `0x0a47a768…2fead4`; plan 5h Task 8d retired it
  for one PQZH id per parameter set (`…/v2`), and the R0 review fix (2026-10-25) bumped those to
  `keccak256("scaas/pqz/pqzh/ligero-fq<log2q>-n<n>k<k>t<t>-keccak256-zk-proven/v3")` (the set's field and preset;
  `n2304-kmax4096`: `0x046859a8…944ead`; v1 and v2 retired; `pqz-core/params/sets/README.md`, "proofSystemIds per set").
- Calldata (measured, plan 5h Task 8d part 2b, `../params/sets/README.md` "One transaction's gas per relation"): a PQZH
  proof above ≈ 261,909 B does not fit one transaction under EIP-7825's 2^24 regular-gas cap with the EIP-7976 floor.
  PQZH debits fit only at `n2048-kmax1024` (not op 7 M = 4 with the auditor); at `n2304-kmax4096` and
  `n2560-kmax16384` only registration and disclosure fit. PQZH stays the backup system.
- The modified zero-knowledge construction was reviewed (pqzh-ligero.md §12): sound and zero-knowledge in the
  classical random-oracle model. An external review comes before PQZH is used with real value (owner step).
- Open (owner): a 128-bit post-quantum soundness target (against Grover-style quantum search) would need a new
  parameter set and a new id (pqzh-ligero.md §5.1).
