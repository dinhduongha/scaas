## Plan decisions (controller calls, owner may override unless marked owner; recorded in full by B8)

- **U8S-D1 msig minimal form — where it applies.** The owner's rule applies to every **stored** `msig` signature, i.e.
  the three portable purposes (`pop` v2, `kem`, `pqz-key`; they are write-once and copied byte for byte): EVM
  `UARegistry._msig(…, portable = true)` (reached from `_sigOk` by `register`, `setKemKey`, `setPqzKey`) and Soroban
  `check_msig(…, portable = true)` (`register` today; `set_kem_key`, `set_pqz_key` in B3). A transaction authorisation
  (`requireAuthorized` / `require_authorized`) is not stored and keeps today's rule (a slot after the threshold fails).
  Every slot counts its member's weight, native members included (`evm-eoa` by `personal_sign`, `G…` by host auth).
  Failure: `UAPoP` in `register`, `UAUnauthorized` in `setKemKey` / `setPqzKey` (EVM); `Pop` / `Unauthorized` (Soroban).
  Implementation: one pass sums `T` and keeps the smallest slot weight `w_min`; accept iff `T >= N && T - w_min < N`
  (equivalent to "every slot necessary"). Rule: owner 2026-10-31; scope: controller call.
- **U8S-D2 Classical-dominant `msig` on Soroban registers with an empty `pop`, as on EVM.** EVM (CTR-UA-07, accounts.md
  §1.8): "A classical-dominant `msig` has no PoP of its own (its members proved theirs) and registers with an empty
  `pop`" (`_sigOk`: `!_pqEligible(d) ⇒ sig.length == 0`). Soroban today requires a member-signed `pop` for every `msig`,
  so a classical `msig` record copied from EVM is refused on Soroban and one registered on Soroban is refused on EVM
  (P10 "the same bytes on every family" broken; no vector exercises it because `msig-classical`'s members are disabled
  kinds on Soroban). Change (M3): `pq_eligible(d)` (members outside 0x0130–0x0133 weigh less than the threshold) as on
  EVM; not eligible ⇒ `pop` must be empty (else `Pop`), `pop_checked = Chain`, `signable` unchanged (member weight).
  One rule everywhere. Controller call, owner may override (open question 1).
- **U8S-D3 Entry layout (spec §4, C12; no `Registration` layout change).** `Ua(ua) → Registration` with
  `attrs.pqz_key` and `attrs.kem_pk` empty, `attrs.pqz_pop_hash` and `attrs.kem_version` kept; `PqzK(ua) → (Bytes key,
  Bytes sig, Checked)` (`sig` empty and `Checked` = `pop_checked` for a key that came with `register`); `PqzP(ua) →
  Bytes`; `Kem(ua, version) → (Bytes pk, Bytes sig, Checked)` (the `register` version with empty `sig` and `Checked` =
  `pop_checked`, UA8-D4); `KemMax(ua) → u64`. `registration_of` returns exactly what EVM `registrationOf` returns for the
  same history: `attrs.pqz_key` from `PqzK` iff `attrs.pqz_pop_hash ≠ 0` (a key added by `set_pqz_key` is not a
  `register` argument), `attrs.kem_pk` from `Kem(ua, kem_version)`, `pqz_pop` from `PqzP` when the `register` key's proof
  is stored (mirror `UARegistry.registrationOf` line by line; B7 proves it). Every entry extends its TTL on write and read.
- **U8S-D4 Events carry hashes, state carries bytes (CTR-UA-33 extended).** The 16,384 B contract-events limit cannot
  carry a 22,528 B PQZ key or a 16-member `msig` signature. `UaRegistered` keeps its shape (the stored record with `pop`
  → `pop_hash`; `attrs` as stored, so `pqz_key` / `kem_pk` empty); new events `UaPqzKeySet { #[topic] ua, pqz_key_hash,
  pqz_pop_hash, sig_hash, checked }`, `UaPqzPopStored { #[topic] ua, pqz_pop_hash }`, `UaKemKeySet { #[topic] ua,
  #[topic] version, kem_pk_hash, sig_hash, checked }`. Readers take the bytes from the views.
- **U8S-D5 Error codes** continue SOR-D16: `PqzHolder = 13, KemHolder = 14, KemVersion = 15, KemKeyLength = 16,
  PqzPopHash = 17` (SOR-D16) and `KemScheme = 18, PqzKeySet = 19` (new, mirroring EVM `UAKemScheme`, `UAPqzKeySet`).
  `Attrs = 7` stays in the enum, unused after B2 (kept for the code points). Map for `portable.json` `negatives[].expect`:
  `UAPoP → Pop` (or a host error for host-verified parts, plan finding F1), `UAPqzPopHash → PqzPopHash`, `UAKeyData →
  KeyData`, `UAPqzHolder → PqzHolder`, `UAKemHolder → KemHolder`, `UAKemVersion → KemVersion`, `UAKemKeyLength →
  KemKeyLength`, `UAKemScheme → KemScheme`, `UAPqzKeySet → PqzKeySet`, `UAUnauthorized → Unauthorized` (an unregistered
  id: `NotRegistered`, C17).
- **U8S-D6 PQZ attributes on Soroban.** Holders as EVM (UA-6 U3): `mldsa44`, `mldsa65`, `fndsa512`, a PQ-eligible
  `msig` (else `PqzHolder`). A key's length is one of the four set lengths in `portable.json` `sets` (16,384 / 18,432 /
  20,480 / 22,528 B), else `KeyData` (Soroban has no set of its own). `pqz_pop_hash` ≠ 0 and ≠ `keccak256("")` with a key,
  0 without (`PqzPopHash`); a given `pqz_pop` must hash to it (`PqzPopHash`). `proven = false`, `pqz_pop_checked =
  None` always; no `Key` entry for a PQZ key (UA8-D8). `set_pqz_key` is write-once: without a verifier nothing is ever
  replaced (EVM R-cross-set needs the verifier) ⇒ `PqzKeySet`. `store_pqz_pop` is open to anyone, hash-checked, a no-op
  when stored.
- **U8S-D7 KEM records on Soroban** = CTR-UA-32: holders as U8S-D6 (`slhdsa128s` not; else `KemHolder`); versions ≥ 1,
  each `(ua, version)` once incl. the `register` one (`KemVersion`); first byte = scheme 1 (`KemScheme`), exactly 1,601
  B (`KemKeyLength`); signature in the `pop` format over `ua_message(kind, PURPOSE_KEM, kem_record_digest)`; no owner
  check, no revocation; `kem_key_of` follows `KemMax`.
- **U8S-D8 The relayer-checked kind set (spec S3, §6; UA8-D20).** `Chain`: the seven enabled kinds (0x0100, 0x0101,
  0x0102, 0x0108, 0x0120 with chain-verifiable slots, 0x0130, 0x0131). `Relayer(id)`: every other derived kind the
  off-chain verifier checks — `bip340` 0x0103, `schnorr-bn254` 0x0104, `schnorr-bls12381` 0x0105, `bls12381-minsig`
  0x0106, `bls-bn254-minsig` 0x0107, the group kinds 0x0110–0x0113, `fndsa512` 0x0132, `slhdsa128s` 0x0133,
  `zether-bls12381` 0x0141 (until Part Z's Z2 makes it `Chain`, ZS-D8 / finding F7); any other kind stays `KindDisabled`.
  A relayer-checked record: key data checked on chain for length / layout only (the relayer checks canonical form with
  `scaas_ua::keydata`), `keyHash` uniqueness by its `kinds.json` group, `signable = false`, never receivable, never a
  signer (P11.5). An `msig` slot is `Relayer` when its member is a registered relayer-checked UA (key read from
  `Ua(id).key_data`, weight 0 for `signable`) or an `evm-contract` member (spec §6); the node never submits an
  `evm-contract` slot (no off-chain ERC-1271 check, C14). Without `relayer` such a part is `NotVerifiable` (today's error).
- **U8S-D9 Gen-1 kind gate (owner 2026-10-31, option (a)).** `DeployBase._checkGen1Kinds(IUARegistry reg, bool bls, bool
  isHedera)` runs at the end of `_deployUARegistry`, before `_gate`: when the probe passes EIP-2537 (`bls`), the gen-1
  registry must enable `schnorr-bls12381` 0x0105, `bls12381-minsig` 0x0106 and, except on Hedera (no Zether token can
  exist there, `ZetherLayer`), `zether-bls12381` 0x0141, else the deploy reverts `"gen-1 registry: EIP-2537 kind <k> the
  probe passes is missing"`. No `UARegistry` change. Soroban: no code — its kinds are compiled in, there are no
  generations, and a new kind is a new registry deployment with new tokens bound to it (S16); the recorded rule is "a
  Soroban registry meant to stay (mainnet) is deployed from a build carrying every kind built for Soroban at that time"
  (so after `zether-soroban`). Gate: owner; the Soroban half: controller call.
- **U8S-D10 Relay-fee minimum: research only** (R1). The owner rules; nothing is built here. A ruling that changes
  contracts is planned before the freeze (work order item 7); a node-config ruling goes with P6i.
- **U8S-D11 Order and T14.** Everything but B10 runs before 2026-11-03. T14 runs on its own (work order item 1); after it
  lands on `main`, `main` is merged into `ua8-soroban` (owner's go not needed for a merge *into* the branch; controller

- **U8S-D12 NEAR and Algorand.** No UA registry exists on either today (base family contracts only); the minimal form

## Open questions for the owner (none blocks a task; each has a default the round proceeds with)

1. **U8S-D2 — classical-dominant `msig` on Soroban.** Today Soroban demands a member-signed `pop` where EVM demands an
   empty one, so such a record cannot be copied in either direction. Default: Soroban follows EVM (empty `pop`).
   Alternative: both families require a minimal member-signed `pop` for every `msig` (EVM change, more gas, one more
   vector regeneration).
2. **G1 — a probe RPC that fails.** `_precompiles()` fails closed (an RPC that refuses `eth_call` with no `to` disables
   the BLS12-381 kinds), so a gen-1 registry can still miss 0x0105 / 0x0106 / 0x0141 for good on a chain that has
   EIP-2537. Default: the stated rule only (the gate fires when the probe passes). Alternative: refuse a gen-1 deploy
   when the probe call itself fails.
3. **R1 — the relay-fee minimum.** The owner picks one of R1's options; if it is the on-chain floor (d), it is built
   before the freeze, otherwise with P6i.
4. **M2 — a moved `debit_min_gas`.** Not expected (the change touches only the portable `_msig` path); if a set's pin
   moves, re-pinning `pqz-core/params/sets/*/set.toml` is a set-parameter change: full pqz-core gate or not is the
   owner's call (M2 Step 5 stops there).
