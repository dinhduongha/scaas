## How to run this plan

- **Two parts.** Part R (R1–R4) is pre-freeze and small: branch `pqvault-r` from `main` **after PR #18 (`ua-mtx-merge`)
  has merged, on the owner's word**; it merges into the contracts line on the owner's word. Part V (V0–V15) may follow the
  freeze, branch `pqvault-v` from the tree that holds Part R. R1 → R2 run in order (each commit green); R3 is independent
  of them and may run in a parallel worktree; V starts when R3's outcome (extracted or copy) is known.
- **Each task is one subagent run**: read AGENTS.md, the spec sections named, the files named; TDD (the failing test first,
  run it red, then the code, run it green); one change at a time for every refusal, each with its positive twin.
- **Heavy commands** through `scripts/capped`, foreground, never inside `timeout`; no background shell, no `anvil` left
  running; Docker not used. From `smartcontracts/evm`: `../../scripts/capped forge …`.
- **Logs.** Full output to `smartcontracts/evm/runs/<YYYY-MM-DD>-pqvault/<task>.log` (git-ignored as `*.log`); commit only
  `runs/<YYYY-MM-DD>-pqvault-summary.txt` lines `task | step | commit | rc | counts`, no absolute path, no `/tmp`. A gate
  that stops resumes per step: read the summary first, skip steps already green on the same commit.
- **Pins.** Gas pins move only with old → new figures in the commit message; layout and typehash pins never move in Part
  R; `size-baseline.json` rows old → new with the reason. A red pin is reported with its output, never edited to green.
- **Commits.** One per task, local, staged by explicit path (`git commit --only -- <paths>` in a shared worktree), English,
  the attribution lines of the session, no `Signed-off-by`. **No push**, no merge: the owner decides.
- **Contract gate** (named "the forge gate" below): `forge test` at the default set over every directory; the set-sensitive
  tests at the other three sets (`script/pqz/at-set.sh <set> test` with the set-sensitive match, `PqzSet.sol` restored);
  the size gate (`T=$(mktemp -d); forge build src --sizes --json > "$T/sizes.json"; python3 ../../scripts/size_gate.py
  "$T/sizes.json" size-baseline.json`).
- **Stop and ask** when: a release runtime passes 33,594 B (a body module is the owner's call); the UA library's
  deployment no longer fits one transaction; R3's acceptance fails (then R3b and a note); a timing or memory measurement is
  needed (V0); any owner rule seems to conflict with the code.

checks that read raw state to compare.

- **Real keys and crypto:** members' UAs registered with their KEM keys (ML-KEM-1024 + X25519); wraps to those keys;
  Argon2id on the vault passphrase at the pinned `passKdf`; AES-256-GCM-SIV items with the padding buckets; FN-DSA-512
  per-vault UAs.
- **Personal vault:** create (mode 0), add items, edit, and a version conflict (two devices write `n + 1`; one is refused
  `PqVaultVersion`, the other merges and writes `n + 2`).
- **Recovery:** a second device holding only the seed and the passphrase recovers the vault list (index vault first), the
  epochs and the latest items from state alone and decrypts them; every item equal byte for byte to what was written.
- **Wrong passphrase:** `PassphraseWrong` before any item is opened (a recording test SDK shows no item open was asked).
- **Shared vault:** member B, on its own seed, decrypts every item A wrote, and A every item B wrote.
- **Sharing a personal vault:** by the copy into a new shared vault (O1 (c)): B reads the copies, and nothing of the
  personal vault (its history, tombstones and epochs stay unreadable to B).
- **Remove and rekey:** after removing B, B cannot open any version written after its removal (no wrap to it, no `K_v`),
  still opens what it could read before, and the admin's affected-items list equals the items whose latest version B
  could read.
- **Both modes:** mode 0 (portable) with a replica instance, the replica's bytes fetched and checked against the home (a
  divergent replica version detected); mode 1 (chain-bound) on one instance, the same scenario.
- **Review r2 R13:** a vault whose admin is an `msig` with a native member, in both modes (the typed-digest and the
  `UAAuth` signing forms); a member who rotated its KEM key (an old wrap under `keyId` 1, a new epoch under `keyId` 2);

- **Mutants**, at least one per decryption check, each killed: skip the wrap-hash check; skip the `sealedInfo` tag check
