## Global constraints (read before every task)

- AGENTS.md: `cargo`, `anvil`, `npm`, `dart`, `cmake` / `ctest` through `scripts/capped`, **foreground**, never inside `timeout`,
  never in the background; no `sleep` / `until` / `pgrep -f` loops; no background shell or `anvil` left behind (tests start and stop
  their own). The e2e step (anvil + a local `scaas-node` + PQZ proofs) runs with `CAPPED_MEM=6G` and no other capped job of this agent
  beside it; everything else at the default 4 GB.
- Local only: in-process fakes on `127.0.0.1:0`, `anvil`, the gas-capped fake chain (T10), a node built from this tree, the families'
  local networks via `smartcontracts/scripts/devnet.sh`. Never the live testnet stack, its containers or its RPC port. Inputs as real
  directories in this worktree (`smartcontracts/evm/lib` via `scripts/evm_libs.sh install` then `check`;
  `clients/clientkeys/node_modules`).
- TDD in every task: write the test, run it, **see it fail for the stated reason**, implement, run it green. Every negative test has
  its positive control beside it. Each task's mutants (listed) must each turn a named test red, one at a time, through
  `clients/scaas-sdk/runs/2026-11-17-scaas-sdk-t<n>-mutants.py` (a list of `(file, old, new, test command)`, modes `run` and `check`);
  record `…-t<n>-mutants.txt` committed (last line `N mutants, N killed, 0 survived, 0 not loaded`).
- Byte formats change everywhere at once: a new format, MAC or derivation gets its clientkeys code and vector rows **first**, then
  `ua-rs`, then the SDK; vectors are regenerated by their generator, never edited by hand.
- No cryptography in `clients/scaas-sdk`: a task that needs a hash of a signed format, a MAC, a KDF, an AEAD or a key adds it to
  `ua-rs` (with clientkeys first), never to the SDK (CLI-SDK-01). No HTTP client in the SDK: everything through `scaas-rpc`.
- The surface rules of spec §16.1 for every public item (owned types, `Arc` objects, string ids, no fixed arrays, every exported async
  call spawned on the SDK's runtime), checked by T3's generator run in every later task's gate (`bind-dart`). **`bind-cpp` is not applicable** in every task
  below until T20b (owner 2026-11-18, Q-B1 (b) for scaas-app's Qt; (a′) the sync C++ surface for third parties, built in T20b;
  spike record `runs/2026-11-17-scaas-sdk-t3-spike.md`).
- `scaas-ua` is taken with `default-features = false` everywhere; the `features` step's `cargo tree -e features` check holds one PQZ
  set.
- Every new input bounded by length and depth; no secret, URL or body in an error, event, `Debug` or `tracing` line;
  `clippy::{unwrap_used, expect_used, panic, indexing_slicing}` denied in `src/`.
- Never edit a pin, a bound or a test to go green; a red stops the task and is reported with its output.
- New source files carry `// SPDX-License-Identifier: LicenseRef-Vegan-Community-1.0` (JS `//` too). Code, comments, commits in English.
  No consumer-specific name in the crate. No absolute or `/tmp` path in a committed file; temp dirs by `mktemp -d` at run time.
- Gate logs: `clients/scaas-sdk/runs/2026-11-17-scaas-sdk-<step>.log` (git-ignored by `*.log`; first line `# <step> at commit <sha>`,
  last `rc=<n>`), progress lines on stdout (start, ok N/M, FAIL, a heartbeat every ~30 s). Only
  `clients/scaas-sdk/runs/2026-11-17-scaas-sdk-summary.txt` (`step | commit | rc | counts`) is committed. On resume read the logs
  first; a step done at the same commit on a clean tree is skipped.
