# UA-2b — the `ed25519` kind: pure-Solidity strict Ed25519 (incl. SHA-512), vectors, T-FUZZ set, registry enablement — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the second of three UA-2 sub-plans ([roadmap](2026-10-12-ua-roadmap.md); owner 2026-10-12): the `ed25519` kind
(0x0102) end to end — a pure-Solidity verifier with SHA-512 that follows RFC 8032 strictly (the semantics of
ed25519-dalek `verify_strict`), its vectors in `signatures.json` (a derived row, the RFC 8032 §7.1 tests, crafted
strictness cases), the T-FUZZ differential set `ed25519_fuzz.json` (2144 cases, each verdict from dalek `verify_strict`,
noble cross-checked), a Rust `verify_strict` arm in `scaas-ua`, and the kind enabled in the registry's test configuration
(its slot exists since UA-2a). Also a one-line fix of a latent Yul evaluation-order bug in `Bip340Verifier` found while
building this. Not here: MuSig2 / FROST (UA-2c), deployment configs per chain (UA-3).

**Architecture:** `Sha512` (unrolled, memory-only) and `Ed25519` (extended twisted Edwards coordinates, `[S]B + [k](−A)`
by Straus–Shamir with 4-bit windows over one doubling chain, a precomputed base table, one `MODEXP` each for the square root
and the inversion; `R` is never decompressed — the computed point's encoding is compared with `R`, as dalek does) are
libraries; `Ed25519Verifier` (`IUAPopVerifier`, `verifyPop == verify`) applies the strict rules and returns false on any
malformed input. One generator writes both vector files; noble (with the two rules it lacks added) and dalek must agree on
every case, and forge requires the dalek verdict on every case.

**Tech Stack:** Solidity ^0.8.20, Foundry (forge 1.3.5, osaka), `MODEXP`; Node 22 with `@noble/curves` 2.4.0 (already a
dependency); Rust 1.90, `ed25519-dalek = "=2.2.0"` (default features off, `fast`; adds `ed25519`, `ed25519-dalek`, `digest`
to the lock).

**Spec:** `docs/contracts/accounts.md` §1.6 (row 0x0102; key data `y < p`, not `x = 0` with the sign bit, not small order),
§1.9 (row `ed25519`: RFC 8032 strict over the 32-byte `ua_msg`), CTR-UA-23 (enabled on every EVM chain; cap measured,
≤ 50 % of the budget on public chains), §1.15, §1.16 (T-FUZZ), S10, S15.

**Base:** `main` at the commit that adds this plan (parent `8bbac31`). Both parts were built as spikes in scratch copies on
2026-10-12 and run green: vectors node 9/9, Rust 2 + 1 + 6 + 6; Solidity: verifier 13 tests (3 fuzz × 256), registry
suites 41, full forge 1009 passed / 0 failed / 10 skipped, size gate 0 errors. Not run in scratch: the merged tree, CI.

## Review Focus

- **Strictness parity:** every class where noble and dalek differ (small-order `R` incl. the identity, `R` or `A` with a
  torsion component) gives dalek's verdict in Solidity; `S + L`, `S ≥ L`, non-canonical `A`/`R`, the 8 small-order points
  are refused; a mixed-order `A` with `[k]T = O` is accepted.
- **SHA-512 correctness at the edges:** 111/112-byte padding boundary, multi-block messages, dirty memory past the free
  memory pointer, 64-bit carries — a wrong hash still verifies nothing, but makes valid signatures fail.
- **Malformed input never reverts:** wrong lengths, off-curve `A`, `y ≥ p`, zero-length messages via `verifyRaw`; gas of a
  rejected signature bounded by the cap.
- **Registry enablement doesn't weaken older tests:** the gen-2 tests that used ed25519 as "a kind gen 1 lacks" now deploy a
  gen 1 without it and still test the same thing; the msig structure bound with an ed25519 member stays ≤ `verifyBudget`.
- **Yul evaluation order:** in `and(staticcall(...), eq(returndatasize(), 0x20))` the right argument runs first and reads the
  previous call's return size — no such pattern left in `src/`.

## Rulings (docs vs code) and defaults taken

- **B1** Strict = dalek `verify_strict` (above); noble `zip215:false` differs on three classes (small-order `R` with
  `S = k·a`; `R` with a torsion part; `A` with a torsion part under the cofactored equation) — dalek is the reference; the
  node test adds the two missing rules and fails on any other disagreement.
- **B2** Canonical `A` is checked on the Rust side too (dalek's `VerifyingKey::from_bytes` does not, curve25519-dalek#626),
  matching `UAKinds` / `keydata.rs`; the Solidity verifier also refuses `A` with `y ≥ p` (unreachable for honest keys).
- **B3** One generator writes `signatures.json` (append-only: `derived[7]` `ed25519`, top-level `ed25519Rfc8032`) and
  `ed25519_fuzz.json` (2144 cases from a fixed seed, keys sorted for forge's `parseJson`; `valid` is the reference verdict,
  `noble` informational).
- **B4** `ed25519-dalek = "=2.2.0"`, default features off.
- **B5** The stale `Cargo.lock` files of `scaas-ua-cxx`, `scaas-ua-qt`, `scaas-ua-frb/rust` (missing UA-2a's crates, now
  also ed25519-dalek's) are refreshed when those crates are next built, not here.
- **B6** Registry cap for `ed25519` = 210 k (measured worst 171,376 + ~23 %), far under §1.15's 1.5 M; §1.15 and CTR-UA-23
  get the measured numbers (Task 5).
- **B7** `P = 2^255 − 19` is passed into the curve code as a function argument (the compiler otherwise rebuilds the
  constant at each of ~3,000 uses: 187 k → 128 k gas); SHA-512 rounds fully unrolled (54 k → 30 k per block).
- **B8** `UARegistryBase.KINDS` lists all 8 derived kinds; gen-2 tests that used ed25519 as "a kind gen 1 lacks" deploy a gen
  1 without it (`_gen1WithoutEd25519()`).
- **B9** The `Bip340Verifier._sqrtCandidate` Yul expression is split so `returndatasize()` is read after the `MODEXP` call
  (Task 4). Effect today: none on acceptance — a MODEXP that succeeds returns 32 bytes, and the stale size came from the
  preceding `ecrecover`; at worst a false rejection — but the pattern is wrong and must not be copied.

    ///        signature is `r ‖ s`, `S` little-endian).
    function verify(bytes32 pk, bytes memory message, bytes32 r, bytes32 s) internal view returns (bool) {
        uint256 sv = _rev(uint256(s));
        if (sv >= L) return false;
        uint256 a = _rev(uint256(pk));
        uint256 ya = a & MASK255;
        uint256 rr = _rev(uint256(r));
        uint256 yr = rr & MASK255;

    function _recoverX(uint256 y, uint256 sign) private view returns (bool ok, uint256 x) {

import {Ed25519} from "../../common/Ed25519.sol";

/// @title UA verifier for `ed25519` (0x0102, accounts.md §1.9).
/// @notice keyData = `A` (32), sig = `R ‖ S` (64), RFC 8032 strict verify (ed25519-dalek `verify_strict`: canonical

///         message, no prehash. `verifyPop == verify`. Wrong lengths and every malformed encoding return false.
contract Ed25519Verifier is IUAPopVerifier {
    function verify(bytes calldata keyData, bytes32 message, bytes calldata sig) public view returns (bool) {
        return verifyRaw(keyData, abi.encodePacked(message), sig);
    }

    function verifyPop(bytes calldata keyData, bytes32 message, bytes calldata sig) external view returns (bool) {
        return verify(keyData, message, sig);
    }

    /// The same check over a message of any length (RFC 8032 §7.1 vectors; not used by the registry).
    function verifyRaw(bytes calldata keyData, bytes memory message, bytes calldata sig) public view returns (bool) {
        if (keyData.length != 32 || sig.length != 64) return false;
        return Ed25519.verify(bytes32(keyData), message, bytes32(sig[0:32]), bytes32(sig[32:64]));
    }
}
