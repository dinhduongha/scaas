## T11 — Real-crypto end-to-end run, local

Owner 2026-11-17: "OK, put the e2e into the pqchat-core plan" (CLI-PQC-12). **Real keys, real wraps, real ciphertexts, no stand-in
wrap**: the stand-in wraps of today's on-chain PqChat runs (`smartcontracts/evm/script/onchain/PqChat.s.sol`, `_wraps`) test the
contract only and are not used here. **Files:** `clients/pqchat-core/tests/e2e.rs` (`#[ignore]`), `tests/e2e/harness.rs`,
`tests/e2e/matrix.rs` (a test-only `MatrixTransport` over matrix-rust-sdk at `app-matrix`'s pinned version, a dev-dependency),
`clients/pqchat-core/runs/2026-11-17-pqchat-core-e2e-mutants.py`.

**Setup (harness, each part started and stopped by the test):**

- **Chain:** `anvil` through `scripts/capped`, the registry, factory and a `PqChat` release with two instances (home and replica)
  deployed by the contract's own forge script (`DEPLOY_PQCHAT`). Signers that need no precompile: `fndsa512` and `mldsa65` on the
  registry's cached expanded key. anvil does not enforce EIP-7825's 2^24 per-transaction cap, so the harness refuses to send any
  transaction with a gas limit above 2^24 and asserts each receipt under it. A run with an `mldsa87` signer, which verifies only by
  precompile, uses a local Nethermind with the precompile instead (Docker, `--memory 4g`, a local data directory made by `mktemp -d`,
  never the testnet stack), as the step `pqc-e2e-nethermind`.
- **Matrix:** one Synapse container (`--memory 1g --cpus 1`, spec §13 O10), two users registered through its shared-secret admin
  API, a third for the group case; the test's transport implementation logs each in once.
- **Accounts:** three seeds in the SDK's vault (test seeds made at run time), UAs A (`fndsa512`), B (`mldsa65`, cached), C (`fndsa512`),
  each registered with a KEM key, version 1, by self-relay from anvil's funded accounts.

**Steps (each asserted; every write through `pqchat-core` over the SDK):**

- [ ] **1:1 session.** A creates a session with B, home the first instance, stores the Matrix room and the home's chain store; the
      wraps are hybrid KEM wraps to B's and A's registered KEM keys (`kemKeyOf`); B finds it by `sessionsOf`, sees it pending,
      accepts, joins the room.
- [ ] **Send and decrypt.** A sends a `text`; B's client receives it from the room and from the chain store, shows it once, and the
      decrypted content equals A's content byte for byte; B replies; A decrypts.
- [ ] **Rekey with removal.** A creates a group session with B and C (A admin). C reads a first message. A removes C (`remove`) and
      rekeys without C; A sends under the new epoch; C's client finds no wrap of its own, holds no `K` for the new epoch, and does not
      decrypt the new message from either store (asserted on C's client: nothing shown, nothing sent); C's plain rekey of the old epoch
      is refused by the contract (`PqChatNotMember`) and C's `postMessage` under the old epoch is refused (`PqChatEpochTaken`).
- [ ] **Fresh device.** A new store for B (same seed, a new device id): `sessions` finds both sessions from state alone (factory index,
      `sessionsOf`, `epochsOf`), opens B's wraps, reads the latest messages from `storedRange` and the room's history, decrypts them
      equal to what was sent; B sends from the new device; A decrypts it.
- [ ] **Replica.** The session's records copied to the second instance: B's client reads the epoch there and accepts it only as equal
      to the home's; a different record under the same id landed in the replica (A signs a second session record with the same nonce)
      is not counted, and membership comes from the home.
- [ ] **Public topic.** A creates a topic; A posts; B replies and votes; the pages from state show them; an entry of the replica
      instance referenced with its `contentHash` resolves as verified.
- [ ] **Mutants, one per decryption or verification check**, each applied alone and turning a named e2e assertion red, through the
      mutants script: K2 unwrap without the KEK's `kemPkHash`; K5 without the message AAD; envelope opened without its check (a
      garbage `env` accepted); V1 skipped (a message signed by C under B's sender field shown); the membership check read from the
      replica; the home slot ignored (a losing child's message shown as current); the counter check dropped (a replayed envelope
      shown twice); `messageId` dedupe dropped (the same message shown twice from two stores); the replica equality skipped; the
      factory listing skipped (an unlisted instance read); the pending gate removed (B's client joins before acceptance). Record
      `…-e2e-mutants.txt` (all killed).
- [ ] Gates: `pqc-e2e`, then `pqc-e2e-nethermind` if an `mldsa87` signer is in the run; per-step logs; the summary row with the
      transaction hashes of the run's writes.
- [ ] Commit `pqchat-core T11: real-crypto e2e, local (CLI-PQC-12)`.
