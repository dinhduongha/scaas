## Global constraints

- Owner rulings override code; a difference between code and CTR-CHAT-01 or the spec is a bug in the code. Follow the
  stated rule; no added assumptions, no option tables.
- **Explicit parameters:** one named typed entry per operation, typed EIP-712 structs (spec §4); `Wrap` as named fields;
  node JSON with named fields; old hex forms refused (`HEX_ARGS_REFUSED`).
- **Every write relayable** by anyone, without a fee field (owner answer 4); payment only through `MtxRelayFee`.
- **No EIP-7702.** No assumption about a chain: no gas price 0, no block limit of ours in code; the code-size limit is a
  constructor argument (spec P11).
- **Never lose ciphertext** (here: a stored message's ciphertext and header stay in state; only the signature is a hash in
  state, D11). Nothing here touches a PQZ or Zether ciphertext. Zether ≠ PQZ; NEAR ≠ Algorand.
- **Nothing deployed is upgraded; backup, do not delete.** A changed release is a new deployment; superseded code moves to
  `legacy/`.
- **One rule on every chain.** The home-chain rule is the same on every chain (each chain compares its own `chain_uid`).
- **The node is open:** the call-table rows and job shapes go in `docs/node/job-api.md`, for every consumer.
- **Byte formats change everywhere at once:** `clientkeys` generates `smartcontracts/vectors/pqchat/`; every reproducer
  reads the same rows; editing one alone is a defect. A digest reproduced in a client is tested with non-zero values in
  every field.
- **Negative tests can fail:** each new refusal has a positive control, one change at a time, and its mutant killed.
- **Heavy commands** through `scripts/capped`, foreground, never inside `timeout`; no background shell or `anvil` left. No
  gas or timing calibration without asking (figures from forge `--isolate` are measurements, not calibration).
- **Docs:** status tags; `docs_check.py check` and `facts check` rc = 0; English only; Mermaid for flows.
- **Git:** stage by explicit path; one commit per task at least; every new test fails before its fix (the red line in the
  commit message); nothing pushed or merged.

## Families

EVM first (this plan). Every other family takes `PqChat` in its own round (`pqchat-<family>`, owner 2026-11-04),
Soroban, NEAR and Algorand each separately; until then a family has no `PqChat` and its node adapter refuses the call kind.
One rule on every chain: the same records, ids and epoch rule.

## Clients

`ua-rs` is the reference (T11); `ua-qt` on libQuotient next (T12, T13; Qt 6.12, built as `docs/clients/` says); the JS
wallet after (T14). The other `ua-*` clients read the vectors when they gain a chat feature; none is required by this plan.

## Pins

- **Typehashes** of the six structs and `DS_C` are pinned in `PqChatTypes` tests and in the vectors.
- **Storage layout** of `PqChat` pinned under `test/v2/layout/`.
- **Gas pins** new in T9; later moves only with old → new figures and a reason in the commit.
- **Sizes:** `PqChat` gets a `size-baseline.json` row; `UARegistry` / `UARegistryLib` grow in T3 (old → new figures).

## What stays research

The unlinkable mode (spec §13, `docs/research/pqchat-unlinkability.md`); MLS groups and an off-chain ratchet for 1:1;
per-device KEM keys. A home-chain move is not planned at all (O3). None is built here.
