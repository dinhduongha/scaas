  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01TeUZDfWK1yvggvyoczLHqr`. Use explicit `git add <paths>`.

  Commands are checked by a worktree guard: avoid `cd x && git`, `$(...)` around agy/grok, complex pipelines with
  git; write helper scripts in your scratch dir when needed.
- Odoo tests: `CHAIN_TEST_DB=<your db> CHAIN_TEST_PORT=<your port> ./scripts/chain-odoo-test.sh <modules> [tags]`.
  Never DB `dms_test` or `odoo19`, never port 8899. One Odoo test run at a time per stream. Long commands:
  run in background, never chain sleeps.
- Toolchains in user space only (rustup targets, `cargo install`, local `npm i` inside your dir, binaries in
  `~/.local/bin`). No sudo, no system changes. Docker images may be pulled; containers must use your ports and be
  stopped when you finish.
- Do NOT read `/home/dockers/odoo19/custom-addons/bamboo-dms/docs/dms/`.
- Prose in docs: Vietnamese with English identifiers; market-neutral (no country law).
- Odoo 19 traps: `models.Constraint` not `_sql_constraints`; cron body in a model method; RPC entry points public
  (no leading `_`, no `@api.private`), never accept company ids from clients; no field named after a type.
- Owner invariants: allowance/approval only to CONTRACT spenders, only contracts call transferFrom (R26); client
  signs, server never signs for a subject (except explicitly delegated capped custody); per-contract lanes/nonces,
  never a subject's account sequence as ordering (R30); expiry + no replay everywhere.
