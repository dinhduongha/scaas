**Goal:** the UA-3 row of the [UA roadmap](2026-10-12-ua-roadmap.md): `zether-bn254` (0x0140) and `zether-bls12381` (0x0141)
in `UARegistry` generation 1 (`authRef` bound by the PoP and co-signed, `requireZetherAuthorized`, `Y` stored for
`keyOf`), `ZetherTypes.toUA` tagged, `ZetherLayer.registered` by `kindOf`, the prover and clientkeys Zether changes in one
change set (CTR-UA-22), the Zether-era `UniversalAccountRegistry` and `AuthScheme` to `legacy/ua3/` (owner: backup, not
delete), `DeployBase` deploying the UA registry on every chain with deploy-time precompile probes (the UA-2 carry-overs),
and an e2e on a dev chain. Gate: T-ZET, e2e on dev chains. Not here: `pqz-mlwe` 0x0142 and the PQ kinds (P6c), the UA
ledger (UA-4).

**Architecture:** The registry gets two kind slots (12, 13) for the Zether kinds, verified by two new `UASafeVerifier`s
that run the existing Schnorr under the Zether tag (`ZetherSchnorrBn254Verifier`, `ZetherSchnorrBls12381Verifier`, dev
chains only). `register` now implements §1.8 steps 5–7 for Zether (`authRef` 0 / native / registered SIGNING, never
Zether nor same-curve BLS; PoP over `popDigest(ua, authRef)`; the authority's `authPop` through `requireAuthorized`
with purpose `authref`) and stores `Y` with SSTORE2 like a group key, so `keyOf(ua)` serves CTR-ZTH-50.
`requireAuthorized` refuses Zether UAs; `requireZetherAuthorized(ua, digest, auth, zkCovered)` is their one check
(self: the proof, or a Zether Schnorr over `uaMessage(kind, zether-owner, digest)`; else the authority under
`zether-auth` / `zether-owner`). The token derives `UA = keccak256(TAG(kind) ‖ Y)` and asks `kindOf`. The prover and
clientkeys compute the same tag, PoP digest and `ua_msg` (pinned by the UA-1 vectors and by `r33_keys.json`, which forge
registers on a real registry). `DeployBase` deploys generation 1 everywhere with the §1.9 kind set; `UAPrecompileProbe`
(constructor returns its verdict) runs through `eth_call`, so the chain's own 0x0c / 0x0e / 0x08 / 0x0f decide.

## Review Focus

- **Front-running and replay of the authority:** a PoP made for `authRef = 0` replayed with an `authRef`, a valid PoP
  without the authority's co-sign, a co-sign for another `(ua, authRef)` — each reverts (`UAPoP` /
  `UAUnauthorized(authRef)`), and a relayer submitting the right data gets the identical record (T-REG-3b,
  `test_T_REG_3b_zether`).
- **Purpose confusion:** an authority's `zether-auth` signature never authorizes a roll-over or mode change and its
  `zether-owner` signature never a spend; a self owner op signed under `zether-auth`, the raw digest, or the UA Schnorr
  tag fails; a Zether signature never verifies as `schnorr-bn254` and vice versa (S13) — `test_zetherAuthorizedSelf`,
  `test_zetherAuthorizedByAuthRef`, `test_zetherVerifiers`, `ZetherAuthRef.t`.
- **A Zether key never signs elsewhere:** `requireAuthorized` on a registered Zether UA fails whatever the auth; a Zether
  UA is refused as an `authRef`, and (UA-2a) as an `msig` member — `test_T_AUTH_1b_registeredZether`,
  `test_authRefRefused`.
- **One id in three languages:** the tagged UA, the PoP digest and `ua_msg` agree between Solidity, Rust and JS (the
  UA-1 rows and `r33_keys.json`); the old untagged id is never registered on a token — `ua_identity_matches_ua_vectors`,
  `test_s3PopRegisters`, `zether.test.js`, `test_registeredByKind`.
- **Fail closed at deploy:** a chain whose precompile is absent, does not check the subgroup, or prices above the
  registry's caps gets no kind that needs it (never "registrable but unusable", CTR-UA-23), and an RPC that refuses the
  probe disables them — `test_probeFailureDisables`, `test_probe` (osaka and cancun).

## Rulings (docs vs code) and defaults taken

- **Z1** Zether kinds are **stored kinds**: `register` writes `Y` with SSTORE2 (`keyPtr ≠ 0`) and `IUARegistry` gains
  `keyOf(bytes32 ua) → bytes` (the stored key of any stored kind; empty otherwise; gen 2 asks gen 1). Reason: CTR-ZTH-50
  (owner) needs the recipients' keys from storage alone, while §1.8's `Record` comment and the §1.15 row assumed Zether
  key data in calldata. §1.8 step 8, CTR-UA-17 and §1.15 are updated (Task 6).
- **Z2** A self Zether UA's owner op is `auth = abi.encode(bytes(""), sig)` (the stored-kind shape of CTR-UA-17; `Y`
  from `keyPtr`); non-empty key data is refused; an `auth` that does not ABI-decode reverts without data, as UA-2a's
  `requireAuthorized`.
- **Z3** **Purpose follows the digest** for every signer: proof-covered `authDigest` (`zkCovered`) ⇒ `zether-auth`;
  roll-over / mode digests ⇒ `zether-owner`, for self and for an `authRef`. The purpose table (CTR-UA-10: `zether-owner`
  wraps "the Zether rollOver/mode digests") and the `IUARegistry` comment ("else requireAuthorized(authRef,
  PURPOSE_ZETHER_AUTH, …)") disagree; the table wins, the comment is fixed (Task 6).
- **Z4** The same-curve BLS rule checks the `authRef`'s own kind (`zether-bn254` refuses `bls-bn254-minsig`,
  `zether-bls12381` refuses `bls12381-minsig`); an `msig` authority's members are not inspected (the registry keeps no
  structure key data) — added to S12's residual (Task 6).
- **Z5** A native `authRef` is any non-zero id with the top 96 bits zero (no code or existence check, as everywhere
  native ids are named); a derived one must be registered SIGNING here or in the predecessor (`kindOf`), so a Zether UA
  or an unregistered id is `UAAuthRef`.
- **Z6** Generations: gen 2 hands a gen-1 Zether record's `requireZetherAuthorized`, `keyOf` and `recordOf` to gen 1
  (`UAVerifyGas` re-raised), mirroring `requireAuthorized`; gen 2 cannot enable a Zether kind whose group gen 1 enables
  (the existing constructor rule).
- **Z7** The Zether Schnorr verifiers are two `UASafeVerifier`s in `PairingVerifiers.sol` (`CHECK_GAS` 40 k / 60 k, caps
  50 k / 70 k as `schnorr-*`); their constructors require a dev chain, so the CTR-ZTH-02 gate moves from the registry
  (which now deploys everywhere) to them.
- **Z8** `ZetherTypes` carries the two tag hashes as constants and picks the tag by the length of `Y` (128 ⇒ BLS12-381,
  else bn254; a wrong length gives an id no registry holds) — no `UAKinds` dependency in the token.
- **Z9** `size-baseline.json`: `NoUnderlyingZetherToken` 31,162 → 31,412, `UnderlyingZetherToken` 40,706 → 40,951
