# DEX round (EVM): no minimum-fill floor, four matching modes, `mtxHybrid`, `mtxExchangeBatch` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** build the accepted DEX round on EVM: the signer's `minFill` as the only per-fill minimum (CTR-DEX-14), the
hybrid entry `mtxHybrid` / `mtxHybridVia` (makers at their own price, the taker gets every unit above the outside floor
and a refund of an unsold remainder under its own bounds), `mtxExchangeBatch` with per-plan isolation, the wrapped
interaction failure, tests that prove modes 3 and 4, the reference executor `UniswapExecutor`, the opt-in Uniswap fork
test, the node / clientkeys changes the round needs, vectors, docs and decisions.

**Architecture:** one branch `dex-round` (worktree `.claude/worktrees/dex-round`) from `main` at the start of the build.
Contracts first (T1–T10, one worktree, sequential: they share `SCaaSDex.sol`), the node and clientkeys after or beside
them (T11–T14; T11 and T14 may run in parallel with T2–T8 because their files are disjoint), then docs (T15–T16), the
gate runner (T17), the whole-branch review and fix wave (T18), the report (T19). The TradeEngine planner (spec §7.2) is
**not** built here (TODO step 6).

**Tech Stack:** Solidity / Foundry v1.8.5 (`evm_version = "amsterdam"`, `via_ir = false`), OpenZeppelin (in `lib/`);
Rust `scaas-node` (alloy, tokio; anvil for the e2e); Node `node --test` (`clients/clientkeys`); Python 3 (`docs_check`,
`size_gate`).

**Spec:** `docs/superpowers/specs/2026-10-30-dex-round-design.md` (accepted by the owner 2026-10-30; §0 DX1–DX22).
Rules: `docs/contracts/dex.md` (CTR-DEX-13 … -26), `docs/node/dex-venue.md` (NODE-DEX-01 … -18),
`docs/clients/signers-clientkeys.md` CLI-SGN-35, `docs/contracts/accounts.md` CTR-UA-24 (EIP-7702 rulings D1–D5).

## Global Constraints

Binding rules of the design (restated without change; the spec's §0 row in brackets):

- [DX1] Per-fill minimum = the signer's `minFill` only: `sellFill ≥ minFill || sellFill == amount − pulled[h]`; no
  received-side line; `minFill > amount` ⇒ `BadMinFill`; `minFill = 0` valid (`ZeroFill` still refuses 0).
- [DX2, DX5, DX6, DX8, DX9] `mtxHybrid(HybridPlan, Interaction[])` / `mtxHybridVia(HybridPlan, address, bytes)`,
  `HybridPlan {ref, taker, makers[], outsideSell, outsideFloor, extraTokens[]}`; listed market; makers at
  `⌈fill · receiveAmount / amount⌉` with `mtxSettle`'s self-trade rule; taker `fill == Σ maker receive + outsideSell`
  (`FillMismatch`), floor `Σ maker fill + outsideFloor`, fee once on the floor, surplus fee-free and the taker's only;
  makers emit `LegSettled` / `UALegSettled`, the taker `ExchangeLegSettled` / `UAExchangeLegSettled`; `LISTED_POOLS`
  read from the taker only.
- [DX7, owner 2026-10-30] A route that leaves `leftover` of the taker's sell token A: `leftover > outsideSell` or A below
  its expected balance ⇒ `ConservationBroken(A)`; else, in this order, `sold = taker.fill − leftover` must be > 0
  (`ZeroFill(h)`), ≥ the taker's `minFill` (`BelowMinFill(h)`), and `sold · receiveAmount ≤ floor · amount`
  (`PriceLimit(h)`), else the whole hybrid reverts; then the leftover is refunded to the taker's `from`, fee-free,
  shown in the taker's event as `sold` (the sold part) and `refund` (leftover + Path B remainder); makers never get it.
- [DX10, DX11, owner-confirmed 2026-10-30] `mtxExchangeBatch(ExchangePlan[], Interaction[][]) returns (bool[])`, path
  (a) only, one self-call `exchangeOne` per plan, `ExchangeFailed(ref, reason ≤ 256 B)`, `SigCheckGasStarved` /
  `UAVerifyGas` re-raised, `NothingSettled`, `LengthMismatch`; every path (a) interaction failure reverts
  `InteractionFailed(uint256 index, address target, bytes reason ≤ 256 B)`, no return data copied on success.
- [DX12] No new signed struct; `trade_kat.json`, `uatrade_kat.json` unchanged.
- [DX15] `UniswapExecutor`: v3 callback + v4 `unlock` hops, exact-input on whole balances, only its DEX, pool callbacks
  checked, holds nothing after a call, no admin; constructor dependencies must be contracts (D5).
- [DX16] The fork test reads its RPC URL only from `SCAAS_FORK_RPC_URL`, never commits or logs it, skips when unset,
  is not in CI.
- [DX18] EIP-7702 D1–D5: no new guard; the submitter and the order relayer binding stay open roles (D3); interaction
  targets and executors unguarded (D4).
- [DX19] Non-EVM families are not touched.
- [DX20] `dex_order_kat.json` regenerated + three encoding-only keys; nothing else under `test/vectors/` or
  `smartcontracts/vectors/` changes.
