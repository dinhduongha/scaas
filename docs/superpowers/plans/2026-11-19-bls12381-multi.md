# `bls12381-multi` (0x0121) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status (2026-11-19):** PLANNED, nothing built. **UNAUDITED**: the batched member PoP (spec §4), the DSTs and the minimal
form are designs; this round builds them and the external audit reviews them later.

**Goal:** Build the UA kind `0x0121` `bls12381-multi` (weighted t-of-n BLS12-381 same-message multi-signature with a signer
bitmap) on EVM, in every client, in the vectors, the node and scaas-sdk, in one round.

**Architecture:** A stored kind: the registry validates the key data `d`, checks the members' aggregate PoP (n + 1
pairings), and stores `p = ua ‖ s` (`s` = `d` with 48-byte limbs) in an SSTORE2 pointer. A new verifier
`BlsMultiBls12381Verifier` checks `σ ‖ signers` against `apk(S)` with one PAIRING_CHECK; the registry calls `verify` on the
hot path and the new `verifyMinimal` on every stored or hash-committed path. Clients reproduce the bytes from shared
vectors; the node and the SDK carry named `signature` and `signers` fields.

**Tech Stack:** Solidity 0.8.37 / Foundry 1.8.5 (Amsterdam, EIP-2537 precompiles), Rust (ua-rs on arkworks
`ark-bls12-381`; scaas-node on alloy 1.6; scaas-sdk), JavaScript (clientkeys on `@noble/curves` 2.4.0), Python (`py_ecc`),
Go (gnark-crypto), C#, Dart, the C / C++ / Qt / Flutter bindings over ua-rs.

**Spec:** [`specs/2026-11-19-bls12381-multi.md`](../specs/2026-11-19-bls12381-multi.md), revision 3. Every task's
requirements include the spec section it names; this plan does not repeat the spec's byte layouts or rules.

## Global Constraints

- Kind `0x0121` (289), name `bls12381-multi`, tag `scaas.ua.bls12381-multi.v1`; id `keccak256(TAG(0x0121) ‖ d)`; no keyHash.
- `d = apk (256) ‖ u16 t ‖ u16 n ‖ n × (pk_i (256) ‖ u16 w_i)`, length `260 + 258·n`; `s` = the same with 48-byte limbs,
  length `196 + 194·n`; stored `p = ua (32) ‖ s`, length `228 + 194·n` (spec §2).
- `2 ≤ n ≤ 64`; `w_i ≥ 1`; `1 ≤ t ≤ Σ w_i`, the sum in at least 32 bits; **no other weight bound** (owner ruling R2-Q3).
- `DST_MULTI_SIG = "SCAAS-UA-V1_BLS12381G1_XMD:SHA-256_SSWU_RO_MULTI_SIG_"`, `DST_MULTI_POP =
  "SCAAS-UA-V1_BLS12381G1_XMD:SHA-256_SSWU_RO_MULTI_POP_"`, 53 bytes each (spec §3).
- Signature ABI: `σ (128) ‖ signers (32, uint256 big-endian)`, exactly 160 bytes; node JSON, SDK and client APIs carry
  named `signature` (128 B) and `signers` (strictly increasing indices `< n`); one 160-byte hex is `HEX_ARGS_REFUSED`.
- Verify path `W(S) ≥ t`; stored paths also `W(S) − min_{i∈S} w_i < t` (spec §5.3, owner ruling Q7).
- `apk(S)`: all n → stored `apk`; `2k ≤ n + 1` → add the signers; otherwise subtract the non-signers (spec §5.2, pinned).
- SDK gas table: optional `per_member` on base and verify rows, absent = 0; quote `gas + per_member × n` (owner ruling R2-Q2).
- No new registry error; failures map to `UAKeyData(0x0121)`, `UAPoP`, `UAUnauthorized(ua)`, `UAVerifyGas` (spec §5.2).
- New source files carry `SPDX-License-Identifier: LicenseRef-Vegan-Community-1.0`. Code, comments, docs in English. No
  absolute or `/tmp` path in any committed file.
- Rule ids `CTR-UA-47` … `CTR-UA-56` are placeholders until Task 18 (spec header).

## Review Focus

Inputs the spec implies that no spec test row names; each has its test in the owning task.

1. **Weight-sum overflow.** Weights are `u16`; `W(S)` and `Σ w_i` exceed 65,535 at two members. A 16-bit sum wraps and turns a
   refusal into acceptance. Row: n = 2, weights {65535, 65535}, t = 65535: {1} authorises and is minimal, {1, 2} authorises
   and is not minimal, `Σ w` check passes. Tests in Tasks 1, 3, 5, 6, 11–15.
2. **Builder order versus index order.** The key data is sorted by `pk_i`; a caller lists members in its own order. A builder
   that sorts keys but not their weights, or an aggregator that takes the caller's indices, signs for the wrong members.
   Row: members given in reverse order with distinct weights give the same id as the sorted input, and the builder returns
   the index map. Tests in Tasks 2 and 3.
3. **The add / subtract boundary.** `2k = n + 1` (odd n) and `2k = n + 2` are the two sides of the pinned path. Rows at n = 5,
   k = 3 (add) and k = 4 (subtract), n = 64, k = 32 (add) and k = 33 (subtract), each equal to the all-add reference. Tests in
   Tasks 1, 3 and 6.
4. **Node `signers` field.** Unsorted, duplicate, empty, an index ≥ 256, a non-integer, or a `signature` that is not 128
   bytes: each refused with a named error before any send. Tests in Task 10.
5. **Quote arithmetic.** `per_member × n` with a table value near `u64::MAX`, or `per_member` on a row whose entry has no n:
   the parse bound refuses the row, the quote never wraps. Tests in Task 16.

## How to run this plan

- **Branch.** `bls-multi`, cut from `ua-rs-sign` **after** the SDK gas round there finishes (it is in progress on
  2026-11-19 and edits `clients/scaas-sdk/gas/` and scaas-sdk spec §13.3). Before Task 1 read the round's final gas-table
  format; Task 16 is rebased on it. Work in a worktree (`.claude/worktrees/bls-multi`). Agents commit locally; they do not
  merge or push.
- **Fresh worktree inputs** as real directories, not symlinks: `smartcontracts/evm/lib` (`scripts/evm_libs.sh install`, then
  `check`), `clients/clientkeys/node_modules` (`npm ci --ignore-scripts`), `smartcontracts/algorand/out`.
- **Order.** 1 → 2 (ua-rs) and 3 (clientkeys) can run in parallel after the Global Constraints are fixed; 4 (vectors) needs 1–3;
  5 → 6 → 7 → 8 → 9 (EVM) need 4; 10 (node) needs 7; 11 (bindings and readers: Tasks 11–15) need 4; 16–17 (SDK) need 2, 9 and
  the SDK gas round; 18 (docs) after 9 and 10; 19 (round gate) last before 20 (reviews).
- **Tests first** in every code task: the test, red; the code; green. Every refusal test changes one thing from a valid row
  (positive control first). Mutants per check, each killed by a named test; mutant scripts and `step | commit | rc | counts`
  summaries in `smartcontracts/evm/runs/2026-11-19-bls-multi/` (full output in git-ignored `.log` files, no absolute paths).
- **Gates per task:** the task's own suites and mutants, plus every test that pins what it changes (gas, size, typehash,
  layout, code hash: old → new figures in the commit). The full matrix runs once, Task 19. Each commit body says "full matrix
  pending (round gate)".
- **Heavy commands** go through `scripts/capped`, foreground, never inside `timeout`; the whole node suite needs 6 GB and
  runs alone (`CAPPED_MEM=6G`). After `capped dotnet …` run `dotnet build-server shutdown`. No background shells, no sleep
  loops, no `anvil` left running.
- **Commits:** one per task, staged by explicit path, trailers as the session gives them, no `Signed-off-by`.

**Plan choices** (the controller's, the owner may override): marked *plan choice* where they appear, listed again at the end.
