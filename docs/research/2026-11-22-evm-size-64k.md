# EVM code size against Sepolia's 64 KiB cap

Study of 2026-11-22 for the owner's ruling of that day, quoted: "Sepolia: Xem xét tối ưu code để giảm code size" (Sepolia:
consider optimising the code to reduce code size). Measure and report only: nothing in `smartcontracts/evm/src/` changed, and no
lever is applied. Base `3f4effb60` (`origin/main`). Tags: **[F]** measured fact, with its source; **[I]** inference; **[E]**
estimate, with its method. Raw figures: `smartcontracts/evm/runs/2026-11-22-evm-size-64k/` (`summary.txt`, `sizes.txt`, the probe
`sepolia_limits.py`).

## 1. Result

- **No contract of `src/` exceeds Sepolia's caps.** The largest runtime is `OpenFactory` at 35,238 B, 30,298 B under 65,536 B.
  The largest init code is `UARegistry` at 46,180 B, 84,892 B under 131,072 B. This covers all 180 contracts: 134 from
  `forge build src --sizes --json` and 60 libraries read from their artifacts. **[F]**
- **The brief's starting point is out of date.** `size-baseline.json` has had no `_above64KiB` pin since T66b. The library
  organisation (spec `2026-11-09-t66b-library-organisation.md`) split every token kind into a release plus body modules.
  `WrappedPqzToken` is now a 27,437 B release, and its largest module, `WrappedPqzTokenQ`, is 29,931 B. **[F]**
- **The four PQZ sets do not change this.** At the other three sets the sizes move by at most 92 B, all on PQZ libraries, and
  the largest contracts stay the same (§4). **[F]**
- **Recommendation: no change to `src/` for Sepolia.** No lever is needed, so no gas pin moves and the factory catalogue is
  unaffected. What does bind on public Ethereum is the 60 M deploy line, not 65,536 B (§6). The owner decisions are in §7.

## 2. Sepolia's limits

Measured on 2026-11-22 by `runs/2026-11-22-evm-size-64k/sepolia_limits.py`. It uses public reads only, with no key and no send,
through both `ethereum-testnet` endpoints of `chain-uids.json`. Three runs; 1rpc.io rotates backends, and some of its answers
were rate-limit refusals, which say nothing about the chain. **[F]**

| Question | publicnode | 1rpc.io | Limit |
|---|---|---|---|
| Block gas limit | 199.6 M to 200.0 M | 199.8 M to 200.0 M | about 200 M |
| `eth_call` creation returning 65,536 B | gas-bound: its `eth_call` gas is clamped to 2^24 | ok, 65,536 B returned | runtime **65,536 B** |
| ... returning 65,537 B | `EVM error: CreateContractSizeLimit` | `max code size exceeded: code size 65537 limit 65536` | |
| `eth_call` with init code of 131,072 B | ok | ok | init **131,072 B** |
| ... of 131,073 B | `max initcode size exceeded` | (refused by its plan) | |
| `eth_estimateGas`, runtime 4,096 / 8,192 / 65,536 B | 6,528,310 / 12,846,185 / over its 50 M cap | 6,528,310 / 12,846,185 / 101,303,209 | 1,542.5 gas per runtime byte |

This agrees with the SDK plan's T40 probe (commit `bcf13dff7`, not on `main` at the base): `ethereum-testnet` runtime 65,536 B and
init 131,072 B, found by bisection with `eth_call` creations; fork `amsterdam`. The init limit is twice the code limit, as EIP-7954
sets it. **[F]**

Three findings for deployment on Sepolia:

- **The deposit price.** The slope from 4,096 to 65,536 B is 1,542.6 gas/B, and from 4,096 to 8,192 B it is 1,542.4 gas/B. The
  SCaaS testnet's formula uses 1,530 state gas per byte. Hashing and memory add less than 0.5 gas/B, so the remaining difference
  of about 12 gas/B (+0.8 %) is in the state price. **[F]** for the slopes, **[I]** for the split between state and regular gas.
- **A transaction above 2^24 total gas is simulated as valid.** The 1rpc.io (geth-style) backend estimates a 65,536 B creation at
  101.3 M, which is consistent with EIP-8037: the 2^24 cap applies to regular gas, and state gas is bounded only by the block.
  No transaction was sent. **[F]** for the estimate, **[I]** for inclusion.
- **Public endpoints cap simulation.** publicnode clamps `eth_call` gas to 2^24 and `eth_estimateGas` to 50 M, so neither can
  simulate a full deployment of our larger contracts. A deployment there needs an explicit gas limit (NET-EVM-11 already sets one)
  and a simulation on a fork or a local node. Q4 of CTR-MTX-30's entry in `decisions.md` says the same for public chains.
  **[F]**

## 5. Levers, in reserve

No contract needs a lever for 65,536 B. The figures below are for the owner in case a contract approaches that cap or its T-1 line.
The first three were measured here, on a scratch copy at `3f4effb60`.

| Lever | `OpenFactory` | `UARegistry` | `NormalPqzTokenQ` | `SCaaSDex` | `WrappedPqzRegulatedToken` |
|---|---:|---:|---:|---:|---:|
| none (HEAD) | 35,238 | 35,166 | 34,895 | 33,497 | 31,882 |
| `optimizer_runs` 50 | −455 | −278 | −546 | −540 | −904 |
| `optimizer_runs` 1 | −635 | −375 | −778 | −616 | −1,322 |
| `via_ir`, one file at a time | −230 | −1,862 (init 43,664) | **+3,467** | not built | not built |

- **`optimizer_runs`.** It applies to the whole build. The gas cost was measured on 2026-11-01 (`evm-size-levers.md` §4, lever 4):
  at 50, +130 to +936 gas per call, 5 gas pins broken; at 1, up to +6,078, 15 pins broken, 2 of them behaviour (the verify
  budget). The library-split checklist does not apply, because no code moves. Every bytecode changes, so the CREATE2 / CREATE3
  KATs, every codehash and every gas pin move. Storage layout and typehash pins do not. The four PQZ sets' gas tables would move.
  Not recommended: about 1.5 % gain for gas on every path.
- **`via_ir`.** Mixed: it shrinks the registry by 5 % and grows `NormalPqzTokenQ` by 10 %, past its module T-1 line. Turning it
  on per contract would be a second compiler pipeline for one kind of contract. The 2026-11-01 note found `forge build src`
  killed at the 4 GB cap and no suite run. Not recommended.
- **Structural levers** (from `evm-size-levers.md`, measured on older code): lever 1 (move `initialize` / table code to a
  library), lever 2 (a shared `nonReentrant` body), lever 3 (views behind `fallback` into a module), and the T66b body-module
  split. Each is a module split or a library move, which only the owner may order. Each needs the checklist: DELEGATECALL storage
  (a module shares the token's layout, which `test/v2/layout/` pins), `this` and `msg.sender` (preserved by DELEGATECALL; a
  forward from a module must not re-enter through `address(this)`), return data (the module's stub must bubble it unchanged),
  reentrancy guards (one guard in the release, as T66b keeps it), and the `LinkClosure` DELEGATECALL count pins. A module
  split also adds an entry to the release's `implArgs` and so a new catalogue version. Typehash pins move only when a constant
  is rewritten.

## 6. What binds instead

- **The 60 M deploy line.** The owner's ruling of 2026-11-07 (CTR-GOV-19's Change, T66b) says every deployed contract fits one
  60 M transaction. The size gate's T-1 lines put that at about 35.3 to 35.7 KB, roughly half of Sepolia's cap. `OpenFactory` is
  48 B under its line and `UARegistry` 120 B under. On a 60 M block these two cannot grow, whatever the code-size cap. **[F]**
- **Sepolia's block does not bind.** At about 200 M per block, the largest deployment, `OpenFactory`, needs
  35,238 × 1,542.5 ≈ 54.4 M of deposit. With calldata, execution and the 1.05 margin it asks about 60.4 M. The size gate's formula
  `runtime × 1,530 + 2^24` asks for 70.7 M. Both fit 200 M. **[E]**: the measured slope times the runtime, and T66b's fit of
  the rest (the plain line's 1,694.7 gas/B and 0.2 M, plus 12.6 gas/B).
- **The T-1 lines carry the SCaaS testnet's price.** They were fitted at 1,675 to 1,695 gas/B, with the 1.05 margin
  included, of which 1,530 × 1.05 is the deposit. Suppose Ethereum mainnet after Glamsterdam prices a state byte as Sepolia
  does today (+12 gas/B, +12.6 with the margin). Each 60 M line then drops by about 250 B, to about 35,130 B for a release and
  about 35,030 B for a plain contract. `OpenFactory` and `UARegistry` would be about 210 B and 140 B over a 60 M block.
  **[E]**: T66b's line formula with the per-byte price raised by the measured difference. Whether the price depends on the
  block gas limit (EIP-8037's cost per state byte) is not settled here. Decision Q4 already says the gate on a public chain is the measured gas × 1.05 against that chain's block limit, so the real check is a
  simulation on mainnet's fork when Glamsterdam arrives.

## 7. Recommendation and owner decisions

**Recommendation.** Make no change to `src/` for Sepolia: every contract already fits 65,536 B runtime and 131,072 B init, with
at least 30,298 B and 84,892 B of margin, at all four PQZ sets. This is one rule on every chain: nothing is shaped for Sepolia.
Nothing moves to gas pins, and the catalogue, layout and typehash pins are untouched.

**Open for the owner:**

1. **Confirm the study's close.** No code change is made for Sepolia's 64 KiB cap, and the size gate keeps its current lines.
2. **Whether to buy margin under the 60 M line.** This is not for Sepolia, but for a 60 M block if Ethereum mainnet's state
   price ends up like Sepolia's (§6). Take `OpenFactory` and `UARegistry` down by about 0.5 to 1 KB each, by a structural lever
   the owner picks from §5. Or accept a 60 M + 1 % line. Or wait for a mainnet fork simulation after Glamsterdam. No lever is
   recommended before that simulation.
3. **A real Sepolia deployment.** It needs a funded key and the controller's or the owner's go. It would confirm that a
   transaction above 2^24 total gas is included (§2, inferred from one estimate), which is the open fact for every contract above
   about 10 KB on Sepolia.

**Owner's answer (2026-11-22):** "Đóng nghiên cứu, chọn (c). Hiện tại, chưa cần deploy trên chain thật + testnet. Làm sau,
ít nhất sau freeze." In English: close the study and choose (c); no deploy on a real chain or a testnet for now, later, at
the earliest after the freeze.
1. Closed: no code change for Sepolia's 64 KiB cap, and the size gate keeps its lines.
2. Option (c): wait for a mainnet fork simulation after Glamsterdam before any lever for the 60 M line.
3. No deploy on a public chain or testnet now. The Sepolia inclusion check and the fork simulation are after the freeze
   at the earliest (TODO 8i).
